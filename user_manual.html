1. 项目简介 / Overview

YZF Sudoku 是一个面向逻辑解题、技巧研究和训练的 Web/WASM 数独工具。它不仅给出答案，还会保留当前盘面、候选状态、步骤结论、链路、高亮和完整解题路径。

主要功能包括：

  • 普通题串、Library、Sukaku、候选盘、Sudoku Coach JSON 与 SCv7_32 导入。
  • 浏览器本地图片识别、原图对照校正、提示数/出数/候选数角色编辑。
  • 题目生成、指定技巧训练生成、OTP（One Trick Pony）生成、ER/EP/ED 与 YZF 评分。
  • 提示一步、应用提示、自动解题路径、所有可选步骤、路径替换与动态解释。
  • 技巧预设、逐项启停、Whip/gWhip 内存模式、Whip/gWhip 最短长度比较、复杂技巧专属子选项。
  • 手工上色、画圈、删数、画链、区块标记、盘面截图与手机分享。
  • 批量出题、批量解题，以及 TLG Truth-Link 集合逻辑编辑器。
  • 专门的手机做题模式，支持竖屏、横屏和触摸标记。
  • 帮助与现场中心，统一管理自动保存、OCR 草稿、近期题目、任务状态、操作引导、语言、界面外观和诊断信息。

YZF Sudoku is a Web/WASM tool for logical solving, technique research, and training. It preserves the board, candidate state, conclusions, chains, highlights, and full solve path instead of merely returning a solution.

Major features include:

  • Import of plain puzzles, Library strings, Sukaku, candidate grids, Sudoku Coach JSON, and SCv7_32 strings.
  • Local browser OCR with side-by-side review and editable given/solved/candidate roles.
  • Puzzle generation, technique-targeted training generation, and ER/EP/ED/YZF rating.
  • Single hints, hint application, auto-solve paths, available-step search, path replacement, and dynamic explanations.
  • Technique presets, individual toggles, Whip/gWhip memory modes, shortest-length comparison, and advanced sub-options.
  • Manual coloring, circles, eliminations, chains, block marks, board capture, and mobile sharing.
  • Batch generation, batch solving, and the TLG Truth-Link set-logic editor.
  • A dedicated portrait/landscape mobile solve mode with touch-friendly marking.
  • A Help & Workspaces center for autosave, OCR drafts, recent puzzles, task status, operation guides, language, appearance, and diagnostics.

2. 启动方式 / How to Start

普通 Web 版

普通版应通过 HTTP/HTTPS 打开。例如在 web-app 目录运行：

python -m http.server 8000

然后访问 http://127.0.0.1:8000/index.html。直接双击普通版 index.html 可能导致 WASM、Worker 或 OCR 资源被浏览器拦截。

Standalone 版

Standalone 单文件版可直接双击运行，WASM、OCR runtime 和模型应已经内联。

剪贴板读写、图片复制、系统分享、相机和文件保存能力取决于浏览器权限与安全上下文。通过 HTTPS 或 localhost 打开时兼容性最好。

Regular Web Build

Serve the regular build over HTTP/HTTPS. From the web-app directory, for example:

python -m http.server 8000

Then open http://127.0.0.1:8000/index.html. Double-clicking the regular index.html may cause the browser to block WASM, workers, or OCR assets.

Standalone Build

The single-file Standalone build can be opened directly. WASM, the OCR runtime, and models should already be embedded.

Clipboard access, image copy, system sharing, camera access, and file saving depend on browser permissions and a secure context. HTTPS or localhost gives the best compatibility.

3. 界面与操作差异 / Interface & Platform Differences

主界面区域

  • 盘面区：9×9 盘面、提示数、出数、候选数、链路和各种高亮。
  • 顶部入口：应用状态、解释、做题和“帮助与现场”。桌面可保留语言下拉框；窄屏把语言、手册、技巧说明等低频入口收进帮助中心。
  • 主要操作：生成、训练生成、加载、撤销、重做、自动解题、提示一步、应用提示、所有步骤、全屏。
  • 四个页签：操作、技巧、解题路径、可选步骤。
  • 数字盘：供触摸、触控笔和手机做题模式使用。最近一次盘面输入来自鼠标时，普通电脑界面的数字盘自动隐藏；OCR 草稿仍可显示“提示数/出数”角色按钮。

帮助与现场中心

点击顶部“帮助与现场”可打开统一入口。桌面采用居中面板，手机竖屏从底部弹出，低高度横屏从右侧进入。

  • 工作现场：恢复自动保存的盘面与手工标记、未完成的 OCR 对照校正，以及最多 12 条近期题目快照。近期卡片包含 9×9 缩略盘、提示数、已填数、候选格和手工标记数量。
  • 任务状态：持续显示生成、评分、自动解题、批量、OCR、保存和 PWA 更新，不再只能靠按钮转圈判断。
  • 学习与引导：打开双语使用手册、技巧说明，或重新播放快速上手、手工标记、OCR 校正和 TLG 编辑引导。重播 OCR 引导时会先尝试读取剪贴板图片；没有图片或权限不可用时，会自动展开现有图片入口并引导选择文件。
  • 设置与支持：切换中英文和自动/浅色/深色/高对比外观，复制不含题面内容的诊断信息。
  • 语言同步：工作现场、任务状态、诊断、引导按钮、手册与技巧说明会随主界面语言一起切换，不维护互相独立的第二套语言状态。

界面外观与高对比

  • 自动：跟随系统浅色/深色偏好，系统切换时页面即时同步。
  • 浅色：保持原来的明亮分析界面。
  • 深色：盘面、候选、表单、弹窗、手工标记和 TLG 状态全部使用深色分析画布；Truth、Link、删数等逻辑颜色仍保留原语义。
  • 高对比：使用黑白边界、加粗焦点框和形状差异，减少阴影与装饰；不是简单反色。

主题不会改变盘面真值、候选坐标、技巧搜索或 TLG 投影。浏览器启用“减少动态效果”或系统强制颜色时，界面会同步降低动画并保留原生可访问颜色。

首次进入新界面会播放一次四步快速上手引导；完成或跳过后不会重复弹出，可随时从“帮助与现场”重播。重播 OCR 引导时，程序先尝试直接读取剪贴板图片，效果等同于在非输入框区域粘贴截图；若剪贴板不可访问、权限被拒绝或没有图片，则展开“题面输入与导出评分”，用顶层说明卡的“选择图片”按钮打开系统文件选择器。识别完成后，正式 OCR 三步引导会强制接续，即使此前已经看过。操作引导使用浏览器顶层弹窗，即使帮助中心、题库弹窗、OCR 全屏校正或其他高层界面仍在显示，主按钮和“跳过”也应保持位于最上层并可点击。OCR 校正第一步支持直接点击高亮格，点击会转交给真实校正格并自动进入下一步。外观偏好保存在本机浏览器中，并在页面首次绘制前恢复，避免深色模式启动时闪白。

Main Interface

  • Board: the 9×9 grid, givens, solved digits, candidates, chains, and highlights.
  • Top entries: app status, Explain, Solve, and Help & Workspaces. Desktop may keep the language selector; narrow layouts move language, manuals, and other low-frequency entries into the hub.
  • Main actions: Generate, Training Generate, Load, Undo, Redo, Auto Solve, Hint, Apply Hint, All Steps, and Fullscreen.
  • Four tabs: Controls, Techniques, Solve Path, and Available Steps.
  • Number pad: used for touch, pen, and Solve mode. It is hidden in the normal desktop layout after mouse input; OCR drafts may also show a Given/Solved role button.

Help & Workspaces

Use Help & Workspaces in the top bar as the unified low-frequency entry. It is a centered dialog on desktop, a bottom sheet in portrait mobile, and a right-side sheet in low-height landscape.

  • Workspaces: restore the autosaved board and manual marks, an unfinished OCR review, or up to 12 recent puzzle snapshots. Recent cards include a 9×9 preview plus given, filled, candidate-cell, and manual-mark counts.
  • OCR guide interaction: on the first correction step, tapping the highlighted cell proxies the tap to the real correction cell and advances automatically. The guide card’s Next button remains available as a fallback.
  • Task Status: keeps generation, rating, auto solve, batch, OCR, saving, and PWA updates visible instead of reducing them to an unexplained spinner.
  • Learn & Guides: open the bilingual Manual, Technique Guide, or replay Quick Start, Manual Marks, OCR Correction, and TLG Editing guides.
  • Settings & Support: switch Chinese/English, choose Auto/Light/Dark/High Contrast appearance, and copy diagnostics that exclude puzzle contents.
  • Language synchronization: Workspaces, Task Status, Diagnostics, guide controls, the Manual, and Technique Guide follow the main interface language instead of keeping separate language state.

Appearance and High Contrast

  • Auto: follows the operating-system light/dark preference and updates immediately when it changes.
  • Light: preserves the original bright analysis workspace.
  • Dark: uses a dark analysis canvas for the board, candidates, forms, dialogs, Manual Marks, and TLG status while preserving the semantic colors of Truths, Links, and eliminations.
  • High Contrast: emphasizes black/white boundaries, stronger focus rings, and shape differences while reducing shadows and decoration; it is not a simple color inversion.

The theme does not alter board truth, candidate coordinates, technique search, or TLG projection. Reduced-motion and forced-colors system settings are respected.

The four-step Quick Start appears once on the new interface. After it is finished or skipped, it stays hidden until replayed from Help & Workspaces. Operation guides use the browser top layer, so Next and Skip remain above Help, library dialogs, full-screen OCR correction, and other high-level interfaces. Appearance is stored locally and restored before first paint to avoid a bright flash when Dark mode starts.

4. 题面输入与现场恢复 / Puzzle Input & Session Restore

支持的输入

  • 81 字符题串：1–9 为提示数，0 或 . 为空格。
  • Library 冒号格式：可保存当前候选删除状态和用户出数。
  • Sukaku / 候选盘：729 字符 Sukaku，或 81 个候选单元格文本。
  • Sudoku Coach：JSON 或 SCv7_32_ 压缩串，支持提示数、出数和候选 mask。

加载流程

  1. 展开“更多：题面输入与导出评分”。
  2. 把内容放入文本框，然后点击“加载”。
  3. 勾选“剪贴板优先”时，加载按钮会先尝试读取剪贴板文本；读取或导入失败后才使用文本框。

电脑浏览器拒绝剪贴板权限时，可取消“剪贴板优先”后直接加载文本框。手机做题模式中的“题面输入”会返回分析界面并自动展开输入面板。

自动保存现场

程序会在本机浏览器保存当前盘面、候选状态、语言、技巧配置和完整手工标记，下次打开时自动恢复。现场格式 v2 可保存整格/候选着色、圆圈、预删数、正式删数、强弱链、构造链、微型区域、区块草稿和当前标记模式，同时兼容旧版 v1 现场。

“帮助与现场”还能继续未确认导入的 OCR 对照校正草稿，并保留最多 12 条去重后的近期题目。空白启动盘不会进入近期列表。

当前提示预览、解题路径预览和 TLG 逻辑不属于主现场。TLG 请使用“TLG 题库”保存，并定期导出 .tlgdb 文件备份；清除站点数据会同时删除现场、近期记录、OCR 草稿和 TLG 用户题库。

Coach 候选数 mask

userCellCandidates 由 81 个十进制 mask 组成，用 - 分隔。数字 d 对应 1 << d；例如候选 2、3、6 的 mask 为 4 + 8 + 64 = 76。

Supported Inputs

  • 81-character puzzle: 1–9 are givens; 0 or . is empty.
  • Library colon format: preserves current candidate eliminations and user digits.
  • Sukaku / candidate grid: a 729-character Sukaku string or 81 candidate-cell tokens.
  • Sudoku Coach: JSON or an SCv7_32_ compressed string with givens, user digits, and candidate masks.

Loading

  1. Open “More: Puzzle Input / Export / Rating”.
  2. Put the input in the text area and press Load.
  3. When Prefer Clipboard is checked, Load first tries clipboard text and falls back to the text area if reading or import fails.

If desktop clipboard permission is denied, disable Prefer Clipboard and load the text area directly. Puzzle Input inside mobile solve mode returns to the analysis view and opens the input panel.

Automatic Session Restore

The browser locally saves the current board, candidate state, language, technique configuration, and complete Manual Marks state. Session format v2 includes cell and candidate colors, circles, pending and applied eliminations, chain lines, construction lines, Mini-Regions, blocks, and the current marking tools, while remaining compatible with legacy v1 sessions.

Help & Workspaces can also resume an unfinished OCR correction draft and up to 12 recent puzzle snapshots. Recent puzzles are deduplicated, and the initial empty board is never added to the list. Clear Saved Session removes the board, language, technique data, and saved manual marks used for the next restore, but does not clear the board currently on screen.

The current hint preview, solve-path preview, and TLG logic are not part of the main saved session. Save TLG logic in the TLG Library and export a .tlgdb backup regularly. Clearing browser site data also removes local workspaces and OCR drafts.

Coach Candidate Masks

userCellCandidates contains 81 decimal masks separated by -. Digit d corresponds to 1 << d; candidates 2, 3, and 6 therefore use 4 + 8 + 64 = 76.

5. 图片识别与对照校正 / OCR & Review

图片识别完全在浏览器本地运行，不上传图片，也不使用在线 fallback。模型按需加载；首次使用可能下载较大的运行库与模型，后续会使用本地缓存。下载中断时，支持的服务器和浏览器会尝试断点续传。

识别入口

  • 选择图片识别：电脑选择文件，手机可从相册选择。
  • 拍照识别：手机请求后置相机；部分浏览器会弹出“相机/相册”选择器。
  • 从剪贴板识别：电脑读取剪贴板中的图片。
  • Ctrl+V：焦点不在输入框时，可直接粘贴截图。

重播 OCR 引导：从“帮助与现场”点击重播后，程序先尝试读取剪贴板图片。成功时直接识别并进入校正；失败时自动展开图片输入区，并在顶层说明卡中提供“选择图片”按钮。选图识别完成后，正式 OCR 引导自动接续，不需要先进入校正页。

OCR 对照校正窗口

  • 左侧显示识别后的盘面图片，中间显示固定 9×9 校正盘面；点击任一侧会同步选中同一格。
  • 右侧可切换提示数、出数、候选数。提示数显示为黑色大数字，出数显示为蓝色大数字。
  • 提示数/出数模式中，数字会替换当前格；再次输入相同数字会清空。候选模式中，数字用于切换候选。
  • “上一格/下一格”移动选格；“清空”清除当前格；“撤销/重做”处理本次校正历史；“恢复识别结果”回到模型最初输出。
  • “确认并导入”把校正结果作为可编辑 OCR 草稿导入；“取消”放弃本次识别。

电脑与手机

电脑和横屏空间充足时使用三栏对照，并提供“全屏校正”。窄屏手机会纵向排列图片、盘面和控制区；窄屏下全屏按钮可能隐藏。进入 OCR 校正时会退出手机做题模式，避免横屏全屏误进入做题布局。

电脑键盘可使用 1–9、0/Delete/Backspace、方向键、Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z 和 Esc。

导入后的继续校正

确认导入后，若仍有错误，可在主盘面继续编辑。OCR 草稿的数字盘会显示“提示数/出数”角色按钮；选择角色后输入大数字，可继续修正黑色提示数和蓝色出数身份。

OCR 只使用黑色提示数检查唯一解。检查失败不会拒绝导入，而是保留草稿供人工修正；唯一性尚未确认时，不应依赖 UR、AUR 等唯一性技巧。

OCR runs entirely in the browser: images are not uploaded and no online fallback is used. Models load on demand; the first run may download sizable runtime/model assets, while later runs use local cache. Interrupted downloads attempt to resume when supported.

OCR Entries

  • Select Image: choose a file on desktop or a photo from the mobile library.
  • Take Photo: requests the rear camera; some browsers show a camera/gallery chooser.
  • Read Clipboard: reads an image from the desktop clipboard.
  • Ctrl+V: paste a screenshot when focus is not inside an editable field.

Replay OCR guide: replaying from Help & workspaces first attempts to read a clipboard image. On success it recognizes the image and enters correction directly. Otherwise it expands the existing image-input section and provides a top-layer Choose Image action. The formal OCR guide continues automatically after recognition; users do not need to enter correction first.

OCR Review Window

  • The recognized image is shown on the left and a fixed 9×9 correction grid in the middle. Clicking either side selects the same cell.
  • Switch among Given, Solved Digit, and Candidates. Givens are black large digits; solved digits are blue.
  • In Given/Solved mode, a number replaces the cell; pressing the same number clears it. Candidate mode toggles pencil marks.
  • Previous/Next moves selection; Clear removes the cell; Undo/Redo edits correction history; Reset OCR Result restores the original model output.
  • Confirm & Import imports an editable OCR draft; Cancel discards the recognition.

Desktop and Mobile

Desktop and roomy landscape layouts use three columns and provide Fullscreen Review. Narrow phones stack the image, board, and controls vertically; the fullscreen button may be hidden. Opening OCR review exits mobile solve mode so landscape fullscreen remains in the correction editor.

Desktop keyboard controls include 1–9, 0/Delete/Backspace, arrow keys, Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, and Esc.

Further Correction After Import

After confirmation, continue editing on the main board if necessary. An OCR draft adds a Given/Solved role button to the number pad so black givens and blue solved digits can still be corrected.

Only black givens are used for the uniqueness check. Failure does not reject the draft. Do not rely on uniqueness techniques such as UR/AUR until uniqueness has been confirmed.

6. 手动做题与盘面编辑 / Manual Solving & Board Editing

推荐的完整做题流程

  1. 载入题目：粘贴题串、使用图片识别、恢复现场，或生成一题。先确认黑色提示数无误；OCR 题尤其要先校正提示数/出数身份。
  2. 鼠标输入：直接在盘面操作，不需要数字盘。左键当前候选将其设为出数；左键用户填写的大数将其清除；右键候选位置删除或恢复候选。
  3. 触摸/触控笔输入：数字盘自动显示。先选择“出数/候选”和 1–9，再轻触目标格。
  4. 人工分析：需要圈候选、画链、上色或暂存删数时，打开“手工标记”。手工标记与真实候选盘分离，不会因为画了红叉就自动删候选。
  5. 核对逻辑：“提示一步”只预览程序找到的下一步；确认后点“应用提示”才真正写入盘面。也可在“可选步骤”中比较多个合法步骤。
  6. 继续与回退：每次正式出数、候选编辑、应用提示都进入撤销历史。误操作立即使用“撤销”，确认无误后再继续。
  7. 保存现场：要保存真实候选状态，优先导出 Library、Coach 或 Sukaku；要保存颜色、圈、链和区块，使用“截图”。

出数模式

  • 鼠标：左键点击空格中当前真实存在的候选，将其写为用户出数。已被删除的候选不能直接出数，需先右键恢复。
  • 触摸/触控笔：选择数字后轻触空格，写入用户出数。
  • 再次输入该格当前的大数字，可清除用户出数；原始提示数受保护，不能用普通做题操作覆盖。
  • 出数后，盘面候选会按当前局面更新。若填入与规则冲突的数字，状态区会提示局面无效。

候选模式

  • 鼠标：右键候选位置切换该候选；存在时删除，不存在时在不违反行、列、宫约束的前提下恢复。
  • 触摸/触控笔：选择候选模式和数字后轻触空格，切换该候选。
  • 候选模式改的是真实当前候选盘，会直接影响后续提示、自动解题、评分和 TLG。
  • “隐藏候选数”只改变显示，不会删除候选；再次显示后原候选仍在。
  • 手工标记中的“预备删数/正式删数”不是候选模式。前者纯视觉，后者只有点击“应用全部删数”才会写入真实候选盘。

提示、应用与可选步骤

  • 提示一步：显示技巧名、结论、结构和高亮，不改盘。
  • 应用提示：把当前提示中的出数或删数写入当前盘面，并记录到撤销历史。
  • 可选步骤：用于比较同一局面的多个合法步骤。普通点击/轻触只预览；路径替换是另一种操作，不等于直接改当前编辑盘面。

OCR 草稿的特殊规则

图片识别结果可先作为草稿进入盘面，即使提示数暂时不是唯一解也能继续校正。校正完成后再使用需要唯一性前提的技巧，特别是 UR、AUR、DAUR 和 GUR。

电脑与手机的基本操作差异

  • 鼠标：使用 FB 风格直接操作，数字盘自动隐藏。左键候选出数，左键用户大数清除，右键候选删除/恢复。
  • 手机：普通做题优先使用“先选数字，再点格”的大按钮流程。精细候选标记则先选格子，再点大数字键，避免点不中小候选。
  • 开启 TLG 编辑后，盘面点击由 TLG 接管；要恢复普通出数/候选编辑，先关闭“启用 TLG 编辑”。
不要把“画了一个删数标记”误认为候选已经删除。真正改变盘面的入口只有候选模式、应用提示、应用全部删数，以及其它明确写入盘面的操作。

Recommended End-to-End Workflow

  1. Load a puzzle: paste a string, use OCR, restore a session, or generate one. Verify all black givens first; OCR puzzles may need given/user-digit role correction.
  2. Mouse input: work directly on the board. Left-click an active candidate to set it; left-click a user value to clear it; right-click a candidate slot to remove or restore it.
  3. Touch/pen input: the solve layout shows a single-row 1–9 digit strip. The next row provides Value/Candidate, Undo, Redo, Hint, Apply, Marks, and More; Clear is under More. Choose Value/Candidate and 1–9, then tap the target cell.
  4. Analyze manually: open Manual Marks for circles, colors, chains, blocks, or staged eliminations. Visual marks are separate from the real candidate grid.
  5. Check logic: Hint only previews the next program step. Press Apply Hint to commit it. Available Steps can compare multiple legal options.
  6. Continue or recover: formal values, candidate edits, and applied hints enter Undo history. Undo mistakes before continuing.
  7. Save the state: use Library, Coach, or Sukaku for the real candidate state; use Capture for colors, circles, chains, and blocks.

Value Mode

  • Select a digit and click an empty cell to enter a user value.
  • Entering the cell's current user value again clears it. Original givens are protected from ordinary solving edits.
  • Candidates update after a value is entered. A rule conflict is reported as an invalid position.

Candidate Mode

  • Select a digit and click an empty cell to add or remove that candidate.
  • Candidate mode changes the real current candidate grid, affecting hints, auto solving, rating, and TLG.
  • Hide Candidates changes display only; it does not delete candidates.
  • Provisional/Formal Eliminations in Manual Marks are different. Provisional is visual only; Formal is committed only by Apply All Eliminations.

Hint, Apply, and Available Steps

  • Hint: displays the technique, conclusion, structure, and highlights without changing the board.
  • Apply Hint: commits the current placement/elimination and records it in Undo history.
  • Available Steps: compares legal options for the same position. A normal click/tap previews only; path replacement is separate from editing the live board.

OCR Draft Rule

An OCR result may enter as an editable draft even before the givens form a unique puzzle. Correct it before using techniques that require uniqueness, especially UR, AUR, DAUR, and GUR.

Desktop vs Mobile

  • Mouse: FB-style direct input is used and the number pad is hidden. Left-click sets an active candidate, left-click clears a user value, and right-click removes/restores a candidate.
  • Mobile: ordinary solving should use the large “choose digit, then cell” flow. For precise candidate marks, select a cell and use the large digit buttons.
  • When TLG editing is enabled, TLG owns board input. Disable it to resume ordinary Value/Candidate editing.
A drawn elimination mark does not mean the candidate has been removed. Only Candidate mode, Apply Hint, Apply All Eliminations, and other explicit commit actions change the live board.

7. 生成、训练与评分 / Generate, Train & Rate

普通生成

先选择 ER 难度分档，再点击“生成”。可选 Random、Easy、Medium、Hard、Unfair、Extreme 和 Insane。状态栏会显示提示数数量和评分。

训练生成与 OTP

生成配置保持在同一行：Difficulty、训练技巧、OTP、文字过滤。Difficulty 会按当前名称紧凑显示，把主要空间留给训练技巧；文字过滤仍通过弹出面板设置。

  • 不勾选 OTP：选择一个训练技巧后点击“训练生成”，程序反复生成并完整解题，直到路径中包含该技巧。
  • 勾选 OTP 且指定训练技巧：程序先只用 Basic 技巧解到无法推进，再仅搜索所选技巧；只要存在一个该技巧步骤，应用后可由 Full House、Hidden Single、Naked Single 一路解到终盘，就接受为该技巧的 OTP。
  • 勾选 OTP 且未指定技巧：Basic 停滞后搜索全部非 Basic、非 BruteForce 逻辑技巧；命中任意 STTE 关键步骤即接受。

OTP 的 Basic 集合包括 Full House、Hidden Single、Naked Single、Locked Candidates，以及显性/隐性 Pair、Triple、Quad。生成成功后，主盘面停在 Basic 无法继续的状态，方便直接训练关键一步。

OTP 只要求至少存在一个合格关键步骤，不要求 STTE 解释唯一。同一个删数由不同技巧、构型或链路解释，不影响 OTP 验收。文字过滤会作用于关键步骤本身。

评分当前题目

“评分当前题目”会优先识别文本框或当前盘面的格式。普通题使用 puzzle 评分；含候选状态的 Library/Sukaku/Coach 输入使用候选盘评分。结果通常包含 ER、EP、ED，并可能显示 YZFRate。

普通训练和 OTP 生成都使用当前启用的技巧配置及相关子选项。OTP 开关会本地记忆；唯一数、区块、数组和 BruteForce 不能作为 OTP 的指定关键技巧。

Normal Generation

Select an ER difficulty band, then press Generate. Available bands are Random, Easy, Medium, Hard, Unfair, Extreme, and Insane. The status reports clue count and rating.

Training Generation and OTP

The four generation controls stay on one line: Difficulty, Training technique, OTP, and Text filter. Difficulty uses a compact content-sized field so the technique selector retains most of the available width.

  • OTP off: select a training technique and press Training Generate. The program generates and solves until the path contains that technique.
  • OTP on with a selected technique: Basic techniques run to a stall, then only the selected technique is searched. The puzzle is accepted when one matching step leads to Full House, Hidden Single, and Naked Single all the way to the end.
  • OTP on with no selected technique: after the Basic stall, all non-Basic, non-BruteForce logical techniques are searched; any matching STTE key step accepts the puzzle.

The OTP Basic set is Full House, Hidden Single, Naked Single, Locked Candidates, plus Naked/Hidden Pair, Triple, and Quad. On success, the live board opens at the Basic-stalled position for immediate key-step training.

OTP requires at least one valid key step, not a unique explanation. Multiple techniques, constructions, or chains explaining the same elimination do not disqualify the puzzle. Text filtering applies to the key step.

Rate Current Puzzle

Rate Current Puzzle detects the text-area or current-board format. Plain puzzles use puzzle rating, while Library/Sukaku/Coach inputs with candidate state use candidate-grid rating. Results normally include ER, EP, ED, and may include YZFRate.

Normal training and OTP generation both use the enabled technique configuration and sub-options. The OTP switch is remembered locally; singles, locked candidates, subsets, and BruteForce cannot be selected as the OTP key technique.

8. 提示、应用与自动解题 / Hint, Apply & Auto Solve

  • 提示一步：按当前技巧开关和顺序寻找下一步，显示结论、高亮与链路，但不修改盘面。
  • 应用提示：把当前提示的出数/删数写入盘面，并进入撤销历史。
  • 解释：当前提示或选中的路径步骤可解释时，顶部“解释”按钮会启用，打开“为什么这一步成立”的动态教程。
  • 自动解题：计算从当前盘面开始的完整逻辑路径，并打开“解题路径”页签。它主要用于查看和比较路径，不会把所有步骤一次性永久写入当前编辑盘面。

耗时搜索在普通 Web 版优先放入 Worker，保持界面可操作；Standalone 或不支持 Worker 的浏览器会回退到主线程。

状态可能显示 solved、NoResult、Invalid 或步数上限等。找不到高级技巧时，先确认技巧已启用，并检查当前题目/候选状态是否合法。

  • Hint: finds the next step under the current technique order, showing conclusions, highlights, and chains without changing the board.
  • Apply Hint: commits the current placement/elimination and adds it to undo history.
  • Explain: when the current hint or selected path step is explainable, the top Explain button opens a dynamic “why this works” tutorial.
  • Auto Solve: computes a full logical path from the current board and opens the Solve Path tab. It is primarily a path viewer and does not permanently apply every step to the editable board at once.

Long tasks use a Worker in the regular Web build when available. Standalone or unsupported browsers fall back to the main thread.

Status may report solved, NoResult, Invalid, or a step limit. If an advanced technique is missing, verify that it is enabled and that the puzzle/candidate state is valid.

9. 解题路径与可选步骤 / Path & Available Steps

解题路径

  • 点击某一步，会把盘面预览到该步执行前，并显示该步高亮；展开节点可查看描述、nodes、edges、rank 和 hash。
  • Force Chain 等多分支提示会显示分支切换控件。电脑还可使用 ←/→ 或 [/] 切换分支。
  • 路径替换后，顶部会显示旧/新步数、评分变化和“撤销分支”入口。

所有步骤 / 可选步骤

“所有步骤”在当前盘面收集多个合法步骤。可使用：

  • 关键词过滤技巧名、删数、格坐标或描述。
  • 按技巧过滤；技巧列表顶部包含 STTE（Single to the End），选择后只显示应用该步骤后，能够仅靠宫末位、隐性单数和显性单数一路解到终盘的候选。这里只迁移 FB checkSTTE 的第一段，不包含 lclSTE、BTE 和更短路径选项。
  • 默认排序，或按“出数/删数优先”排序。
  • “可替换”只显示可绑定到当前解题路径某一步的候选；即使可选步骤结果没有显式的来源步编号，也会依据执行前盘面哈希匹配当前路径。
  • 点击“清除”会同时重置关键词、技巧、排序和“可替换”筛选。

预览与替换

单击/轻触步骤只预览。若步骤标有“可替换”，电脑右键、手机长按约 0.65 秒，会用该步骤替换原路径对应步骤，并从替换点继续重算。与原步骤相同的候选不会替换。

路径和可选步骤中的盘面是预览状态。导出或保存现场前，应返回实际编辑盘面，或明确使用替换后的路径结果。

Solve Path

  • Click a step to preview the board immediately before it and display its highlights. Expand nodes to inspect the description, nodes, edges, rank, and hashes.
  • Multi-branch hints such as Force Chains expose branch controls. Desktop also supports ←/→ or [/].
  • After path replacement, a panel shows old/new step counts, rating deltas, and an Undo Branch action.

All / Available Steps

All Steps collects multiple legal options for the current board. You can:

  • filter by technique name, conclusion, coordinate, or description;
  • filter by technique; the top of the technique list includes STTE (Single to the End), which shows only options after which Full House, Hidden Single, and Naked Single alone solve to the end. This includes only the first stage of FB checkSTTE, not lclSTE, BTE, or shorter-path options;
  • use default order or sort placements/eliminations first;
  • show only Replaceable options that can bind to the current solve path; when an explicit source-step number is absent, the board hash before the option is matched against the current path;
  • press Clear to reset the text, technique, sort, and Replaceable filters together.

Preview and Replace

A normal click/tap only previews. For a Replaceable item, right-click on desktop or long-press for about 0.65 seconds on touch to replace the corresponding original step and recompute the remainder. An option identical to the current step is not replaced.

Boards shown in Path and Available Steps are previews. Before exporting or relying on session restore, return to the live editable board or intentionally use the replaced path result.

10. 技巧配置与高亮 / Technique Settings & Highlights

预设按钮

  • All In：启用全部已实现技巧。
  • High Speed：关闭一批耗时最大的高级技巧，兼顾覆盖率。
  • Extreme Speed：进一步关闭较慢技巧，优先速度。
  • Whip Rating：基础技巧 + Whip/gWhip，并自动使用大内存评分配置；默认返回最短 Whip，可通过下方选项把 gWhip 纳入长度比较。
  • Braid Rating：基础技巧 + Braid/gBraid。

逐项配置

技巧表可逐项启用/关闭，并显示分数与难度颜色。Complex AIC 可单独勾选 with AMSLS，JE 可勾选 with JEPOM。

Whip/gWhip 搜索内存模式：

  • 自动：普通求解使用常规队列，Whip Rating 使用大内存。
  • 普通：速度和内存优先。
  • 大内存：提高搜索覆盖率，但更耗内存。

gWhip 参与最短长度比较：仅在 Whip 与 gWhip 同时启用时生效。程序先取得最短 Whip，再只搜索可能更短的 gWhip；gWhip 严格更短时返回 gWhip，同长度仍优先 Whip。

技巧配置会随主现场自动保存。预设会重置 Complex AIC/JE 的专属子选项，使用后请重新确认。

高亮阅读

一般高亮包括出数、删数、结构格、强/弱链、ON/OFF 节点、ALS/AF 区域、guardian 和分支。点击顶部“技巧说明”打开 techniques.html，查看每个技巧的玩家向解释。

Exocet 系列的颜色分工：整格背景只表达整体构型角色，例如主 Base、主 Target、Cross/S、Double JE 的第二组 Base/Target，以及 Weak Exocet 的 Y 格和 Weak Seat；格内候选不会再用同一种角色色重复涂抹。候选级颜色只用于附加证明规则和结论，例如锁定在 Q/R/T 邻中的非 Base 数、Mirror 支持、Senior Exocet 的 locked non-base、fins/guardians，以及最终删数或出数。没有实际参与结论的临时支持色会被回滚。

Guardian Force Chain

Dead pattern 的 guardian 不可能全部为假，因此至少一个为真。如果每个 guardian 为真都推出同一个结论，该结论成立。UR Guardian FC 与 Triplet Oddagon/Tridagon Guardian FC 使用相同的强制链原则，只是 deadly pattern 不同。

Preset Buttons

  • All In: enables every implemented technique.
  • High Speed: disables a group of the most expensive techniques while retaining broad coverage.
  • Extreme Speed: disables more slow techniques and prioritizes speed.
  • Whip Rating: basic techniques plus Whip/gWhip with the large-memory rating configuration. It returns the shortest Whip by default; the option below adds gWhip to the length comparison.
  • Braid Rating: basic techniques plus Braid/gBraid.

Individual Settings

The technique table allows individual toggles and shows score/difficulty coloring. Complex AIC has a with AMSLS sub-option; JE has with JEPOM.

Whip/gWhip search memory modes:

  • Auto: normal queues for solving, large memory for Whip Rating.
  • Normal: prioritizes speed and memory use.
  • Large: improves search coverage at higher memory cost.

Compare shortest length with gWhip: applies only when both Whip and gWhip are enabled. The solver finds the shortest Whip first, then searches only for a strictly shorter gWhip. Whip wins ties.

Technique settings are saved with the main session. Presets reset the Complex AIC/JE sub-options, so re-check them afterward.

Reading Highlights

Highlights may include placements, eliminations, structure cells, strong/weak links, ON/OFF nodes, ALS/AF regions, guardians, and branches. Open the top Technique Guide link for player-facing explanations in techniques.html.

Color roles in the Exocet family: whole-cell backgrounds express structural roles only, such as the primary Base and Target cells, Cross/S cells, the secondary Base/Target pair in Double JE, and the Y cell or Weak Seat in Weak Exocet. Candidates inside those cells are no longer redundantly painted with the same role color. Candidate-level colors are reserved for auxiliary proof rules and conclusions: locked non-base digits in Q/R/T neighborhoods, Mirror support, Senior Exocet locked non-base candidates, fins/guardians, and final eliminations or placements. Provisional support colors are rolled back when they do not contribute to a conclusion.

Guardian Force Chain

Guardians of a dead pattern cannot all be false, so at least one is true. If every possible true guardian produces the same conclusion, that conclusion is valid. UR and Triplet Oddagon/Tridagon Guardian FC use the same forcing principle with different deadly patterns.

11. 手工标记 / Manual Marks

在“操作”页签展开“手工标记”。它是人工分析层，适合记录假设、制作讲解图和规划删数；除“应用全部删数”外，标记本身不改变真实盘面。

一套完整的使用流程

  1. 先完成题面和候选盘的校正，选中准备分析的格子。
  2. 打开“手工标记”并选择模式与颜色。鼠标直接用左右键；触摸/触控笔使用面板中的成对动作按钮。
  3. 整格模式直接点格；候选模式可直接点小候选，手机也可先点格再点大数字键。
  4. 画链时依次点起点和终点；区块模式逐个选择节点后点“完成区块”。
  5. 预备删数只用于推演；确认成立后改为正式删数，再点“应用全部删数”。
  6. 需要保留讲解现场时立即截图。主现场恢复不会自动保存手工标记。

标记模式

模式作用与使用场景
关闭标记把盘面点击权交回普通出数/候选编辑。
整格上色标出 ALS、AHS、UR 四角、强制链分支区域或人工关注区域。
候选上色区分 ON/OFF、不同分支、不同集合成员。
候选画圈突出关键候选、guardian、链端点或共同结论。
预备删数只画待验证的删除符号，不改变候选，适合试推。

手动画链只画普通强/弱链。鼠标第二端左键＝强链，右键＝弱链；触摸使用“强链/弱链”按钮。
构造链与手动画链分开。鼠标第二端左键＝构造强链，右键＝构造弱链；触摸使用对应按钮。

区块标记本项目扩展能力：连续选择多个当前候选，形成圆形、胶囊或凸包区域。

添加、删除与颜色

  • 选择颜色后，“添加”写入当前模式标记，“删除”移除当前模式对应标记，不会误删其它类型。
  • 颜色选择器可添加自定义色；自定义色保存在当前浏览器。
  • 同一候选可叠加不同类型的标记；看不清时应减少层数，而不是误以为后一次一定覆盖前一次。
  • 链、构造链和微型区域使用成对动作：强/弱、构造强/构造弱、绿色/蓝色。重复相同类型和相同端点会删除该对象。

链、构造链与微型区域

  1. 鼠标画链：先点起点；在第二端使用左键生成强链，右键生成弱链。构造链模式同理，只是线色为橙色。
  2. 触摸画链：先选择“强链/弱链”或“构造强链/构造弱链”按钮，再按“格子 → 大数字键”指定两个端点。
  3. 微型区域：先点起点；第二端左键为绿色胶囊，右键为蓝色胶囊。触摸使用“绿色区域/蓝色区域”按钮。
  4. 删除或改型：同端点、同类型重画会删除；同端点、不同类型重画会原位改型。
  5. 改变箭头方向：同一边改型或重画时，最后一次选择的“起点 → 终点”成为显示方向；判断是不是同一条边时不区分方向。
  6. 撤销最后一边：“撤销线”只弹出链线列表中的最后一条边，不能指定更早的边。删除较早的边应使用第 2 步。
  7. 取消误选起点：第二端点尚未选择时点“取消起点”。切换标记模式也会清掉未完成起点。
最容易误操作的地方：右键在链、构造链和微型区域中代表第二种关系，不是任意对象橡皮擦。删除指定对象要重复同类型、同端点；“撤销线”只撤销当前类别中的最后一项。

鼠标删除旧边示例

假设旧边是 2r1c1 → 7r4c5 的构造弱链：切到“构造链”，左键起点，再右键终点；端点顺序可以反过来。重复完成后该边删除。

手机删除旧边示例

选择对应模式和强/弱（或绿色/蓝色）按钮；轻触起点格和数字，再轻触终点格和数字。重复同类型、同端点即可删除。

电脑操作

检测到鼠标输入后，数字盘、链线下拉框和“添加/删除”按钮会自动隐藏；改用触摸或触控笔操作盘面时会自动恢复。平板连接鼠标时可在两套规则间即时切换。

  • 整格上色：左键格子添加，右键格子删除。
  • 候选类模式：左键候选添加，右键候选删除当前模式标记。
  • 候选颜色、圈和两种删数：可以标记九宫候选位置，即使该候选已从真实候选盘删除。
  • 画链/构造链：第一端任意键；第二端左键为强，右键为弱。重复同类型端点删除。
  • 微型区域：第二端左键绿色、右键蓝色；重复同色端点删除。
  • 区块：右键某个候选会把该节点从草稿以及所有包含它的已完成区块中移除；区块没有节点时自动删除。

手机/触屏操作

  • 整格上色：轻触格子添加，长按格子约 0.6 秒删除。
  • 候选上色、画圈、预备删数、正式删数、区块：先点格子，再轻触大数字键添加；长按同一数字键约 0.5–0.6 秒删除。也可直接长按盘面小候选删除。
  • 不方便长按：先点“删除”，再轻触格子或大数字键，效果相同；但画链是例外，删除指定边要重复选择同端点和同类型。
  • 手机链/构造链/微型区域：先选择成对按钮中的类型，再依次使用“点格子 → 点大数字键”指定两个端点。重复同类型端点删除。
  • 候选类标记会自动显示候选。长按删除只删手工标记，不会直接删真实候选。
  • 做题模式中点“标记”打开面板；面板保持为内嵌形式，显示在盘面/控制区下方，不再切换到抽屉弹层。

链与区块工具

  • 撤销线：在链/构造链模式撤销最后一条线；在微型区域模式撤销最后一个区域。指定旧对象请重复同类型端点。

  • 完成区块：把当前候选节点集合固定成区块。
  • 撤销区块：有草稿时先撤销最后一个节点；没有草稿时撤销最后一个已完成区块。

区块编辑的边界行为

  • 第一个节点确定当前草稿区块的颜色；草稿未完成时再换颜色，不会重染已经开始的草稿。先完成区块，再用新颜色开始下一个。
  • 1 个节点显示圆形，2 个节点显示胶囊，3 个及以上节点按凸包包围。
  • 删除某候选节点时，会同时从当前草稿和所有包含该节点的已完成区块中移除；因此重叠区块也会一起变化。

应用删数与截图

“应用全部删数”只处理“正式删数”，不处理“预备删数”。只会删除执行时仍真实存在的候选；已经出数或已经不存在的旧标记会跳过。成功应用的正式删数标记会移出待应用集合，预备删数仍保留。

勾选“清除简单步骤”后，即使当前没有正式删数，也会尝试连续应用 Full House、Hidden/Naked Single、Locked Candidates、Pair、Triple 和 Quad，直到遇到更高级步骤或无步骤。

“截图”按屏幕当前显示生成 PNG，包含全部手工标记。电脑优先复制到图片剪贴板；手机优先系统分享；能力不可用时回退下载。

与 TLG 的关系

TLG 编辑和手工标记都需要接管候选触摸，因此不能同时操作。开启 TLG 时，普通技巧高亮、链路和手工标记只暂时隐藏；关闭 TLG 后恢复。要继续画普通标记，先关闭“启用 TLG 编辑”。

手工标记会随主现场自动保存并可从“工作现场”恢复。浏览器数据可能被清理，重要结构仍建议截图长期保存；Library、Coach 和 Sukaku 只保存真实盘面/候选状态，不包含颜色、圈、链和区块。

Open Manual Marks in the Controls tab. It is a human-analysis layer for hypotheses, teaching diagrams, and planned eliminations. Marks do not change the live board except through Apply All Eliminations.

Complete Workflow

  1. Correct the puzzle and candidate grid, then select the area to analyze.
  2. Open Manual Marks and choose a mode and color. Mouse input uses left/right clicks directly; touch and pen input use the paired action buttons in the panel.
  3. Cell modes target the cell; candidate modes can target tiny candidates, or on mobile use a selected cell plus the large digit pad.
  4. For a chain, select start and end. For a block, collect nodes and press Finish Block.
  5. Use Provisional Eliminations while testing. Convert confirmed conclusions to Formal Eliminations, then press Apply All Eliminations.
  6. Manual marks are saved with the main autosave session. Capture important diagrams for long-term archiving or sharing, because browser storage may still be cleared.

  • The first node locks the current draft block color. Changing color before finishing does not recolor that draft; finish it and start a new block.
  • One node renders a circle, two nodes a capsule, and three or more nodes a convex hull.
  • Erasing one candidate removes it from the current draft and every completed block containing it, so overlapping blocks may all change.

Apply and Capture

Apply All Eliminations commits Formal Eliminations only, and only candidates that still exist at execution time. Stale marks on solved or already-removed candidates are skipped. Successfully applied formal marks leave the pending set; provisional marks remain.

With Clear Easy Steps enabled, easy-step cleanup is attempted even when there are no formal eliminations. It continues through Full House, Hidden/Naked Single, Locked Candidates, Pair, Triple, and Quad until a higher technique or no step is reached.

Capture creates a PNG exactly as displayed. Desktop first tries the image clipboard; mobile first tries system share; unsupported cases fall back to download.

Relationship with TLG

TLG editing and manual marks both need candidate touch ownership, so they cannot be edited simultaneously. TLG temporarily hides ordinary highlights, chains, and marks; disabling TLG restores them.

Manual marks are saved with the main autosave session and can be restored from Workspaces. Browser data may still be cleared, so capture important diagrams for long-term storage. Library, Coach, and Sukaku preserve the live board/candidate state, not colors, circles, chains, or blocks.

12. 批量任务 / Batch Tasks

批量出题

  1. 选择“批量出题”、输出文件名和主界面的难度。
  2. 未勾选 OTP 时，选择训练技巧会批量输出包含该技巧的普通训练题；未选择技巧则普通批量生成。
  3. 勾选 OTP 时，批量任务沿用主界面的训练技巧和文字过滤：指定技巧则生成该技巧 OTP，未指定则生成任意技巧 OTP。
  4. 主界面的普通训练生成会显示目标技巧出现前的盘面；OTP 生成会显示 Basic 无法继续的关键盘面。两者都不保留临时步骤高亮。
  5. 点击“开始”持续生成，点击“停止”结束并关闭/下载文件。

每行一题，使用制表符分隔四列：序号、Library 题串、YZF 评分、SKFR 的 ER 评分。选择训练技巧后，批量面板的默认文件名会自动使用技巧名称。

批量解题

  1. 选择“批量解题”。
  2. 选择纯文本输入文件，一行一题；空行和以 # 开头的行会忽略。
  3. 点击“开始”，输出每题的状态、步数、YZF 评分、最难技巧和错误信息。
  4. 最难技巧判定：先比较 YZF 分数；同分时按 FB 原版 SolutionType 的固定技巧顺序裁决；只有同一种技巧内部才继续比较 rank/长度。因此同为 400 分时，Cell/Region Forcing Chain 会覆盖先出现的 Complex AIC，不再受解题路径先后顺序影响。

文件与平台差异

支持 File System Access API 的桌面浏览器会先让你选择保存位置，并在运行中持续追加；其它浏览器（常见于手机和部分 Firefox/Safari）会在任务结束或停止时生成下载文件。

批量出题默认持续运行，必须点击“停止”。关闭页面前先停止，否则尚未下载的内存结果可能丢失。

Batch Generation

  1. Select Batch Generate, an output filename, and the main difficulty.
  2. With OTP off, a selected Training technique emits ordinary training puzzles containing that technique; no selection performs unrestricted generation.
  3. With OTP on, batch generation reuses the main Training technique and text filter: a selected technique generates that technique's OTP puzzles, while no selection generates any-technique OTP puzzles.
  4. Realtime normal training opens immediately before the target technique; OTP generation opens at the Basic-stalled key position. Temporary step highlights are not retained.
  5. Press Start to generate continuously and Stop to finish and close/download the file.

Each puzzle occupies one tab-separated line with four columns: index, Library puzzle string, YZF score, and the SKFR ER score. When a training technique is selected, the batch panel defaults the filename to the technique name.

Batch Solving

  1. Select Batch Solve.
  2. Choose a plain-text input file with one puzzle per line. Blank lines and lines beginning with # are ignored.
  3. Press Start. Output includes status, steps, YZF rating, hardest technique, and errors.
  4. Hardest-technique tie-break: compare the YZF score first, then the fixed FB SolutionType order for equal scores; rank/length is compared only within the same technique. Thus, at score 400, Cell/Region Forcing Chain supersedes an earlier Complex AIC instead of depending on path order.

Files and Platform Differences

Desktop browsers with the File System Access API ask for a destination and append while running. Other browsers, commonly mobile and some Firefox/Safari versions, create a download when the task finishes or is stopped.

Batch generation runs continuously by default and must be stopped. Stop before closing the page or in-memory output that has not yet downloaded may be lost.

13. TLG Solver / Truth-Link Logic

TLG Solver 用 Truth、Link 和额外唯一性约束描述一个集合证明，再枚举满足全部约束的投影，从共同结果中得到删数或出数。它不是普通提示器：用户必须明确告诉程序哪些集合和 deadly-pattern 约束属于当前证明。

首次启用 TLG 编辑会播放四步引导，依次说明输入模式、盘面接管、结构核对和“查找删数”。完成或跳过后，可从“帮助与现场 → 工作现场 → 引导重播”再次打开。

勾选“启用 TLG 编辑”后，TLG 独占整个盘面的鼠标、触摸和长按输入以及专属高亮。普通技巧高亮、链路和手工标记只暂时隐藏；关闭 TLG 后恢复。关闭 TLG 会释放临时导入的 TLG 候选盘和计算结果，但保留已输入的 Truth、用户 Link、两组 Virtual Set、AUR、DAUR、GUR 标记。

专用图解布局：TLG 开启时，1～9 候选会切换为横纵坐标都不重复的错切九点布局，便于 Row、Column 与 Box 通道分轨，同时仍保持标准 3×3 的读数方位。蓝色徽标表示结构候选，红色徽标表示最终删数；Cell 淡蓝、Row 紫、Column 绿、Box 褐。颜色只区分对象类型，Truth/Link 由形态区分：Truth 是实心区域，Link 是同一几何的空心轮廓。两组 Virtual Set 使用黑色集合连线并以 1/2 角标区分；AUR、DAUR、GUR 不再画外框，而是用候选徽标角标着色，同组同色、异组异色。普通候选、提示数和已出数字保持正常对比度；关闭 TLG 后立即恢复普通 3×3 候选布局。
输入兜底：TLG 开启期间，Truths 模式左键轻触空候选位置仍按 Cell Truth 处理；除此之外，空候选位置的右键/长按、固定格、出数格，以及非 Truths 模式的单元格空白点击都会被安全忽略。它们不会回落为普通出数、恢复候选、数字盘输入或手工标记。只有关闭“启用 TLG 编辑”后，普通盘面编辑才会恢复。

13.1 先理解四类状态

状态含义什么时候变化
Truths用户输入的“必须恰好覆盖一次”集合。点击、批量菜单或成功转换冗余 Truth 时变化。
用户 Links用户明确指定的“最多覆盖一次”集合，是下一次“查找删数”的输入。用户添加/删除，或成功执行转换/移除操作时变化。
结果 Links最近一次成功计算实际使用/保留下来的 Links，用于结果高亮和后续结构整理。每次成功计算后更新；任何新的 TLG 输入编辑都会使其失效。
删数/出数结果最近一次成功证明的共同结论。成功查找后产生；输入变化后清空。
本次修复后的关键规则：“查找删数”不会再把自动生成的 Links 写进用户 Links。你加一个 Truth 后再次查找，只要用户 Links 仍为空，程序就会重新自动生成 Links；同时，上一轮自动 Links 仍能作为结果 Links 正常高亮。

13.2 用户 Links、自动 Links 与“Link 类型=自动”不是一回事

  • 用户 Links 为空：点击“查找删数”时，后端从当前 Truth、候选盘和额外约束重新生成自动 Links。
  • 用户 Links 非空：这次查找进入显式结构模式，只使用用户 Links，不再混入自动生成 Links。
  • 结果 Links：无论来自自动生成还是显式用户输入，成功查找后的实际结构都保存在只读结果层，用于高亮。
  • “Link 类型=自动”下拉框：只决定你用两个候选点击输入 Link 时，前端如何解释这两个端点；它不控制后端是否自动生成整套 Links。
  • 成功执行“转换冗余 Truths”或“移除未使用 Links”属于明确的结构修改，返回的 Links 会提交为新的用户 Links。此后若想恢复全自动生成，应从“当前 TLG 状态”删除全部用户 Links，或清空逻辑后重建。

13.3 候选盘与唯一性门控

TLG 分开保存初始候选盘与当前候选盘。初始盘用于核验 AUR/DAUR/GUR 的唯一性前提；当前盘用于实际证明。Sukaku 只是候选输入格式，不自动等于训练盘。

  • 唯一解：核验初始可交换局面（默认）：普通数独和唯一解 Sukaku 应使用此项。AUR/DUR/GUR 必须在初始盘存在足够的可交换/等价完成，当前盘仍保留至少一个相关完成。
  • 训练盘：允许初始缺数：只用于人工构造的多解、Rank 或结构训练盘。它跳过原始唯一性前提，只检查当前候选云。
门控选错可能产生伪结论。不是“候选盘格式”就该选训练盘；只要它来自唯一解题目，仍应使用默认严格门控。

13.4 从零开始的完整流程

  1. 把题目解到需要研究的候选状态，并确认当前候选准确。需要独立候选盘时，把 729 字符 Sukaku 或 81 个候选单元格粘贴到题面输入框。
  2. 展开 TLG Solver，选择正确的唯一性门控，勾选“启用 TLG 编辑”。如使用独立候选盘，点击“导入 TLG 候选盘面”；导入时的候选固定为初始盘，之后编辑只影响当前盘。
  3. 先输入 Truths。简单集合可用两个端点点击，复杂/批量集合用右键或手机长按菜单精确添加。
  4. 决定 Link 策略：希望程序自动补 Links 时，不要输入任何用户 Link；需要复现指定结构时，再输入显式用户 Links。
  5. 按证明需要添加 Virtual Set、AUR、DAUR 或 GUR。它们是逻辑前提，不是装饰标记。
  6. 检查“当前 TLG 状态”中的用户输入，确认没有多余集合、错误候选或残留用户 Links。
  7. 点击“查找删数”。阅读结果 Links、删数/出数、Rank、AUR/DAUR/GUR 展开信息和预算状态。
  8. 需要整理结构时，依次尝试“转换冗余 Truths”和“移除未使用 Links”。失败不会覆盖上一轮有效结构；成功则提交新的用户 Truth/Link 状态。

13.5 Truth 怎么输入、什么时候用

Truth 表示投影中必须恰好选择一个成员的集合，支持行数字、列数字、宫数字和单元格集合。

  • 行/列/宫 Truth：在 Truths 模式依次点击两个同数字候选；它们必须共享目标行、列或宫。程序据此加入完整描述符，例如 5R3。
  • Cell Truth：在 Truths 模式点击空单元格背景，或通过批量菜单选择“单元格”。它表示该格必须选一个候选。
  • 批量精确输入：电脑 Ctrl/Command 选候选后右键；手机长按选候选后打开菜单。选择行、列、单元格或宫，程序按每个选中候选生成对应描述符。
  • 只添加你能证明属于结构的 Truth。Truth 过多会改变 Rank 和投影，不是“多标一点更保险”。

13.6 Link 怎么输入、什么时候用

Link 表示投影中最多覆盖一次的集合，也用于判断集合外候选能否被全部投影排除。

  • 推荐默认：先保持用户 Links 为空，让程序自动生成；这是增加 Truth 后反复查找时最稳妥的工作流。
  • 显式 Link：只有在复现指定 TLG、限制搜索结构或人工整理 Rank 时才输入。House Link 通常应由同数字候选定义；Cell Link 由同一格内不同候选定义。
  • 两端点输入：切换到 Links 模式，选择 Link 类型，再点两个候选。自动模式优先把同格端点解释为 Cell Link；否则按共享行、列、宫解释。
  • 批量输入更可靠：批选后从菜单明确选择行/列/单元格/宫，避免端点几何存在多种解释。
  • 只要存在一个用户 Link，本轮查找就不会自动混入其它 Links。需要自动模式时必须把用户 Links 删到 0。

13.7 Virtual Set：怎么用

Virtual Set 用于表达不能方便写成普通 R/C/B/N Truth 的精确基数约束：在一组候选中，恰好有 k 个会被选中。当前支持 Virtual Set 1 和 Virtual Set 2 两个相互独立的集合，每组都有自己的成员与基数。

  1. 把输入模式切换为 Virtual Set，再从“Virtual Set 分组”选择 1 或 2。
  2. 逐个点击当前组的成员候选，或批选后从右键/长按菜单选择“切换 Virtual Set 1/2”。
  3. 在“应用 Truths 数”填写当前所选组的精确基数 k。每组分别支持 1–4；切换分组时输入框显示该组自己的数值。
  4. 确认每组成员都是真实活动候选，并且外部逻辑分别证明“该组恰好 k 个为真”，再查找删数。

两组关系：两组可以完全分离，也允许共享候选。若某个候选同时属于两组，它被选中时会同时计入两组基数；这不是复制候选，而是两个独立等式共同约束同一个布尔变量。

图解：两组都使用黑色集合网络，候选徽标上的小角标 1/2 区分归属；同时属于两组时会显示两个角标。

适用场景：已经由别的结构推得一个或两个候选云分别具有精确 1、2、3 或 4 个真值，但它们不对应单一行、列、宫或单元格 Truth。

不要这样用：不要把“至少一个”“至多两个”或只是怀疑相关的候选随意放入任一组。后端会把每组都当作严格等式前提，错误成员或错误基数会直接污染证明。

13.8 定式 AUR：怎么选、怎么用

定式 AUR 用一个已知的可交换唯一矩形/唯一性结构，强制其本体不能全部按 deadly completion 占满。标准四格 AUR 编译为 maxBodyFootprint ≤ 3。

标准四格 AUR（推荐日常用法）

  1. 切换到 AUR 模式，并选择 AUR 1 或 AUR 2。两组用于同时输入两个独立结构。
  2. 每组只标记两个对角候选点：它们数字不同、行不同、列不同，且位于矩形的两个对角。两点共同定义两行、两列和本体数对。
  3. 例如标记 2r1c1 与 7r4c5，程序据此检查由 r1/r4、c1/c5、数字 {2,7} 构成的四格 AUR。
  4. 严格门控要求初始候选盘同时支持两种交替完成；当前候选盘至少保留其中一种。
标准 AUR 不要把四格中的 8 个本体候选全部都点进同一组。后端会对标记点两两配对，过量标记可能生成重复 AUR 或意外结构。可预期的标准用法是每组精确选择两个对角、异数字候选点。

该标什么：标的是定义 AUR 本体的候选点，不是 guardian、目标删数或矩形外候选。

高级广义 AUR：同一 AUR 组达到 10–64 个候选点时，后端会转入广义/旋转候选云验证，枚举 exact-cover 形式并受预算限制。只有明确知道整组本体候选云含义时才使用；普通 UR/AUR 不需要它。

13.9 DAUR：怎么选、怎么用

DAUR 是动态 AUR/DUR 候选池。你不直接指定某一个矩形，而是给出一小片可能的本体候选，程序从中展开所有成立的标准四格 AUR，以及六格 2×3 / 3×2 DUR。

  1. 切换到 DAUR 模式。
  2. 只标记可能属于目标 AUR/DUR 本体的活动候选；不要把 guardian、目标删数和无关候选放入池中。
  3. 从最小、最明确的候选池开始查找。结果区会显示 DAUR 展开的 AUR/DUR 约束数量。
  4. 若“没有展开出有效形式”，检查候选池是否缺少某个本体候选、当前盘是否还保留 deadly completion，以及严格门控的初始盘是否存在交换前提。

什么时候用：结构中可能存在多个重叠 AUR/DUR，手工逐个指定很麻烦，或你希望程序在已知局部候选池内自动识别。

DAUR 会把候选池内找到的全部有效约束同时加入证明，并不是自动挑一个“最像的”。池过大会增加运行时间，也可能引入你原本没打算使用的结构。

13.10 GUR：具体用途、标准用法与验证案例

GUR（Generic Uniqueness Region，通用唯一性区域）用于验证没有固定模板的可交换 deadly pattern。程序在用户定义的局部格集合中枚举“一格一个数”的合法完成，再比较每个完成占用的行数字、列数字和宫数字 exact-cover footprint。若两种或多种局部完成拥有相同 footprint，它们可以在不改变外部约束的情况下交换；GUR 会把这些 deadly 完成编译为精确禁止条件，再从剩余完整投影中寻找共同删数和出数。

适用对象：不规则 deadly pattern、Qiu Deadly Pattern（QDP）、部分 Reversed Deadly Pattern，以及无法由标准 AUR 或 DAUR 四格/六格模板准确表达的局部唯一性结构。

标准工作流

  1. 准备准确候选盘：从唯一解题目得到的状态使用“唯一解：核验初始可交换局面”；只有人工构造的训练候选盘才使用训练门控。
  2. 确定局部格边界：只纳入参与可交换完成的活动格，不把 guardian、预期删数或仅用于外部连接的格混入 GUR。
  3. 每个参与格添加 Cell Truth：Cell Truth 表示该格在投影中必须选择一个候选。不要误以为只圈 GUR 候选就足够。
  4. 选齐完整 GUR 候选云：对每个参与格，加入该局部模型允许参与完成的全部活动候选。常见的闭合局部模型可先批选这些格中的任一候选，再从右键/长按菜单选择“切换 GUR 通用格”，一次加入每个格的全部当前候选；存在 guardian 或非本体候选时，再用“切换 GUR 通用候选云”逐候选修正。漏候选会制造假的限制，多选无关候选会扩大完成空间。
  5. 第一次查找先保持用户 Links 为 0：让后端从 Truth、候选盘和 GUR 自动生成 Links。结果区显示的 Links 是本轮实际使用的只读结果 Links，不会反写为用户 Links。
  6. 点击“查找删数”：检查 GUR 枚举约束、唯一性门控、预算状态、删数和出数。需要复现指定结构时，才把结果 Links 整理成显式用户 Links。

成功判据

  • 结果显示至少 1 个 GUR 枚举约束，且没有“初始盘不存在等价完成”“当前盘没有存活 deadly 完成”或预算超限。
  • 投影搜索完整结束；预算超限时，“0 个删数”不能解释为已经证明无删数。
  • 预期目标删数或出数出现在结果中。仅看到 GUR 彩色角标不代表逻辑已经验证。
  • 闭合局部模型可能推出教程没有单独列出的额外删数或出数。这通常表示 TLG 使用的完整投影比手工教程结论更强；仍应核对候选云边界是否准确。
当前 GUR 需要覆盖至少 4 个格，安全上限为 16 个格、64 个候选点。典型 18 格 RUR/RUL 超过当前格数上限，不能直接当作已正式支持。

  3. 删除全部用户 Links 后重试自动 Links，避免残留显式 Link 把搜索限制到另一套结构。
  4. 检查唯一性门控是否符合候选盘来源，以及初始候选盘是否在编辑前正确固定。
  5. 若预算超限，先缩小局部区域；不要把超限当作“结构无效”。

13.11 电脑批选、右键菜单

  1. 按住 Ctrl；macOS 按 Command，逐个点击候选。再次点击可取消该候选。
  2. 在任一已选候选上右键，打开 TLG 菜单。
  3. “Truth/Link”子菜单选择行、列、单元格或宫。若所选描述符全部已存在，该动作会移除；否则补充缺少的描述符。
  4. 也可批量切换 Virtual Set、当前 AUR 分组、DAUR 和 GUR。“切换 GUR 通用格”按所选候选所在格一次加入/移除全部当前候选；“切换 GUR 通用候选云”仍用于候选级精确增删。
  5. 使用“清除候选选择”只清除批选，不清逻辑；“清空全部逻辑”清除 Truth/Link/VSet/AUR/DAUR/GUR 和结果，但保留临时 TLG 候选盘。

13.12 手机/触屏 TLG 操作

  • 短按候选：直接执行当前输入模式。Truth/Link 模式先选第一个端点，再短按第二个端点；VSet/AUR/DAUR/GUR 模式短按即切换成员。
  • 长按候选约 0.6 秒：把该候选加入批选并打开 TLG 菜单。菜单子项用轻触展开，不依赖桌面 hover；选择“切换 GUR 通用格”可按格一次加入该格全部当前候选。
  • 选择多个候选：长按第一个候选，轻触菜单外关闭；再长按下一个候选。长按是累加选择，重复直到选完，再在菜单执行批量动作。
  • 重新开始批选：从菜单点“清除候选选择”。不要用普通短按候选来继续批选，因为普通短按会按当前模式执行并清掉原批选。
  • Cell Truth：Truths 模式轻触空单元格背景或已删除候选的空位置，不要点仍存在的候选数字。
  • 误触空位置：除上述 Cell Truth 快捷操作外，空候选位置的右键、长按及其他模式点击都会被忽略，不会修改真实盘面。
  • TLG 开启时，普通手工标记的候选长按处理会暂停，避免两个模式争抢同一次触摸。

13.13 查找、转换与移除的正确顺序

  • 查找删数：观察性操作。它计算结果 Links 和结论，但不修改用户 Links。
  • 转换冗余 Truths：在已有有效结论的结构上，把可转移的冗余 Truth 转成 Link。成功后 Truth 和用户 Link 状态都会按返回结构更新。
  • 移除未使用 Links：在结果结构上删除不参与证明的 Links。成功后精简结果提交为用户 Links。
  • 按钮只有在上一轮存在有效删数或出数时才开放。失败响应不会覆盖上一轮有效输入和结论。
  • 任何 Truth、用户 Link、VSet、AUR、DAUR、GUR 或候选输入变化，都会清空旧的结果 Links 和结论，防止用旧高亮解释新结构。

13.14 高亮怎么读

  • 对象颜色：Cell 淡蓝、Row 紫、Column 绿、Box 褐；结构候选用蓝色徽标，最终删数用红色徽标。
  • Truth / Link：Truth 画成实心区域，Link 画成同一几何的空心轮廓。Row/Column 是连续带，Box 是可转弯、可分叉的正交网络。
  • Cell：区域按该 Cell 约束的活动候选徽标求包围盒，不再整格填色或画整格边框。
  • 候选布局：TLG 保留标准 3×3 候选方位，同时在每个传统区域内错开轨道。横坐标从左到右为 1 4 7 | 2 5 8 | 3 6 9，纵坐标从上到下为 3 2 1 | 6 5 4 | 9 8 7；因此 3 仍在右上、7 仍在左下，而 1～9 又各占唯一的横、纵坐标。
  • 候选：同一候选即使同时属于多个 Truth/Link，也只显示一个徽标；约束身份由徽标下方的几何区域表达。未进入结构的普通候选、提示数和已出数字保持原有对比度，不再为聚焦 TLG 而整体压灰。
  • Virtual Set：黑色集合连线，和 Box Truth 一样允许转折与分叉；AUR / DAUR / GUR：不再使用外围框，改为画在候选徽标角上的彩色角标。同一组使用相同颜色，不同组尽量使用不同颜色。
  • 结果优先级：最终删数红徽标覆盖结构蓝色；约束区域在底层，候选徽标和交互强调在上层。

13.15 结果表示与预算

大写 R/C/B/N 表示 Truth，小写 r/c/b/n 表示 Link，N/n 表示单元格集合。状态区会区分用户 Links 和结果 Links，并显示唯一性门控、活动候选数、AUR/DAUR/GUR 验证信息、删数和出数。

出现“投影解数量超过预算”“搜索节点超过预算”或 GUR 局部完成枚举超预算，表示搜索未完成。此时“0 个删数”不能解释为已证明无删数；应缩小候选云、减少 Truth/Link，或在 native 环境提高预算测试。

13.16 清理命令的区别

  • 当前状态列表逐项删除：只删除对应用户输入。
  • 右键/长按菜单“清空全部逻辑”：清除全部 TLG 逻辑和结果，但保留已导入的临时候选盘。
  • 面板“清空 TLG 状态”：连同临时候选盘一起清除，主数独题目本身不受影响。

13.17 TLG 逻辑题库

“TLG 题库”用于把候选盘、Truth/Link 结构和唯一性约束固化为可重复学习的案例。它与主现场自动保存相互独立：浏览器本地题库适合日常操作，.tlgdb 文件才是跨设备、重装和长期归档的备份。

定长二进制记录

题库采用 YZF 私有二进制格式，每条记录固定为 2048 字节。文件头之后可直接按“文件头 + 序号 × 2048”定位记录，因此读取、原位替换和顺序管理都很直接。每条记录有独立 CRC32 校验；文件头也有校验，损坏时会拒绝导入，而不会把坏数据写入当前题库。

一条记录保存：

  • 原始给定数、当前大数、初始候选盘和当前活动候选盘；
  • 324 位 Truths、324 位用户 Links，以及计算后的结果 Links；
  • 两组 AUR、DAUR、GUR，以及两组 Virtual Set；每组候选云均使用 729 位候选位图；
  • 两组 Virtual Set 各自的精确基数、当前选中的 Virtual Set 分组、唯一性门控、输入模式和 Link 类型；
  • 最近一次删数、出数结果，以及标题、标签、来源和学习笔记。
题库保存结构化数据，不保存依赖界面语言的结果长文本。读取后，程序会按当前中英文设置重新生成状态和结果说明。

读取、插入、替换、追加、删除

  • 读取：恢复所选案例的候选盘、全部 TLG 输入、操作选项和结果快照，并自动开启 TLG 编辑。题库盘面是独立的 TLG 视图；关闭 TLG 后，原来的主数独现场重新显示。
  • 插入：把当前 TLG 保存到所选记录之前；没有选中记录时按追加处理。
  • 替换：用当前 TLG 覆盖所选记录，保留该记录的位置和首次创建时间。
  • 追加：把当前 TLG 保存到题库末尾，生成新的记录 ID。
  • 删除：删除所选记录；执行前会要求确认。

标题、标签、来源和笔记来自题库窗口右侧。题库 v2 仍保持每条 2048 字节，为第二组 Virtual Set 预留位图后，各字段按 UTF-8 字节限制：标题 128、标签 96、来源 128、笔记 507 字节。导入旧版 v1 记录时仍兼容原来的 512 字节笔记。中文通常占 3 个字节；超过当前版本上限会明确报错，不会静默截断。

二进制题库导入与导出

  • 导出选中：生成只含所选记录的 .tlgdb 文件。
  • 导出题库：按当前顺序导出全部记录。
  • 追加到末尾：把导入文件中的记录作为新记录放到题库末尾。
  • 插入到当前位置：把导入记录按文件顺序插入所选记录之前；没有选中记录时追加。
  • 替换整个题库：清空浏览器本地题库，再载入文件中的全部记录；该操作会二次确认。

分享单个 TLG 文字样例

二进制题库适合长期保存和批量管理；论坛、聊天、Issue 或个人笔记中分享一个案例时，可使用 .tlg.txt 文字样例。文字操作针对当前 TLG 工作区以及题库窗口右侧填写的标题、标签、来源和笔记，因此案例尚未存入题库时也能直接分享。

  • 复制样例：复制可阅读的多行 YZF-TLG-CASE:2 格式，其中 VIRTUAL1[k] 和 VIRTUAL2[k] 分别保存两组；字段名固定为英文标识，不随界面语言变化。程序仍可读取旧版 YZF-TLG-CASE:1。
  • 复制单行：复制以 YZFTLG2 开头的紧凑单行格式，使用 W1=/W2= 保存两组；旧版 YZFTLG1 仍可导入。
  • 粘贴样例：尝试读取剪贴板并展开文字框；浏览器拒绝剪贴板权限时，可在框内手动粘贴。
  • 导入文本：读取 .tlg.txt 或普通 .txt 文件到文字框。
  • 导出文本：把当前 TLG 工作区保存为 标题.tlg.txt。
  • 载入样例：解析成功后先显示标题、类型、Truth/Link 数、活动候选和结论摘要；确认后才替换当前临时 TLG 状态，不会自动写入题库。需要长期保存时，再使用“插入、替换或追加”。

文字样例无损保存原题、当前大数、两套候选位图、Truths、Links、AUR 1/2、DAUR、GUR、Virtual Set 1/2 及各自基数、结果 Links、删数、出数、操作选项和元数据。多行版使用可读的 7r3c4 候选和 1r3 约束表示；两套完整候选盘采用 Base64URL 位图。程序导出的文字包含 CRC32，复制被截断或意外改动时会拒绝载入。

.tlg.txt 适合分享单例，但不替代整库备份。多行版和单行版都能重新导入，并恢复为同一套结构化 TLG 状态。
浏览器清理站点数据、无痕模式结束、重装系统或更换设备，都可能丢失 IndexedDB 中的本地题库。完成重要逻辑后应立即导出 .tlgdb；需要公开讨论的单个案例再同时导出或复制 .tlg.txt。

TLG Solver describes a set proof with Truths, Links, and optional uniqueness constraints, enumerates projections satisfying all premises, and derives common eliminations or assignments. It is not an ordinary hint button: the user defines the proof structure.

The first time TLG editing is enabled, a four-step guide explains input modes, board ownership, structure review, and Find Eliminations. Replay it later from Help & Workspaces → Workspaces → Guides.

Enable TLG Editing gives TLG exclusive ownership of all board mouse, touch, long-press input, and its visual layer. Ordinary technique highlights, chains, and manual marks are hidden rather than deleted. Disabling TLG releases the temporary TLG candidate grid and computed result, while keeping the entered Truths, User Links, both Virtual Sets, AUR, DAUR, and GUR marks.

Dedicated diagram layout: while TLG is enabled, the familiar 3×3 candidate directions are preserved. The x tracks run left-to-right as 1 4 7 | 2 5 8 | 3 6 9, and the y tracks run top-to-bottom as 3 2 1 | 6 5 4 | 9 8 7. Thus 3 remains upper-right and 7 remains lower-left, while every digit still receives a unique x/y pair that separates adjacent Row, Column, and Box channels. Blue badges are structure candidates and red badges are final eliminations; Cell is light blue, Row purple, Column green, and Box brown. Color identifies the object type only: a Truth is a filled region, while a Link is the hollow outline of the same geometry. Ordinary candidates, givens, and solved values retain their normal contrast; only candidates replaced by blue/red SVG badges hide their duplicate DOM labels. Disabling TLG immediately restores the ordinary 3×3 pencilmark layout.
Input guard: while TLG is enabled, a plain left tap on an empty candidate slot in Truths mode still acts as the Cell Truth shortcut. Otherwise, right-click/long-press on an empty slot, fixed/solved cells, and cell-background clicks outside Truths mode are safe no-ops. They never fall through to ordinary value entry, candidate restoration, the number pad, or manual marks. Ordinary board editing resumes only after TLG Editing is disabled.

13.2 User Links, Automatic Links, and “Link Type = Auto”

  • No User Links: Find derives automatic Links again from the current Truths, candidates, and extra constraints.
  • Any User Link: Find uses explicit-link mode and does not mix in automatic Links.
  • Result Links: the successful structure is stored separately for highlighting, regardless of whether it was automatic or explicit.
  • Link Type = Auto: only controls how a pair of clicked endpoints is interpreted by the frontend. It does not enable backend-wide automatic Link generation.
  • Successful Convert Redundant Truths or Remove Unused Links is an explicit structure mutation, so its returned Links become User Links. Remove all User Links to return to fresh automatic generation.

13.3 Candidate Grids and the Uniqueness Gate

TLG stores an initial candidate grid separately from the current candidate grid. The initial grid verifies AUR/DAUR/GUR premises; the current grid drives the proof. Sukaku is a format, not an automatic training-mode signal.

  • Unique puzzle: verify initial swap pair (default): use for ordinary puzzles and unique Sukaku. AUR/DUR/GUR needs sufficient swappable/equivalent completions initially and a related live completion currently.
  • Training grid: allow missing initial candidates: only for deliberately constructed multi-solution, Rank, or structure-training grids. It checks the current cloud without proving the original uniqueness premise.
Choosing the wrong gate can create false conclusions. A candidate-grid format does not by itself justify Training mode.

13.4 Complete Workflow

  1. Reach the candidate state to analyze and verify it. For a standalone candidate grid, paste 729-character Sukaku or 81 candidate-cell tokens.
  2. Open TLG, choose the correct gate, and enable editing. Press Import TLG Candidate Grid when needed; imported candidates become the initial grid and later edits affect the current grid.
  3. Enter Truths first. Use endpoint clicks for simple sets and the context menu for precise batch descriptors.
  4. Choose the Link strategy: leave User Links empty for auto derivation, or enter explicit Links to reproduce a fixed structure.
  5. Add Virtual Set, AUR, DAUR, or GUR only when the proof requires them.
  6. Review Current TLG State for stale User Links, unrelated sets, or wrong candidates.
  7. Press Find Eliminations and inspect Result Links, conclusions, Rank, expansion/validation data, and budgets.
  8. Optionally run Convert Redundant Truths and Remove Unused Links. Failure preserves the previous valid state; success commits the returned structure.

13.5 Truth Input and Use

A Truth is a set from which exactly one member must be selected. Row-digit, column-digit, box-digit, and cell sets are supported.

  • House Truth: in Truths mode click two same-digit candidates sharing the intended row, column, or box.
  • Cell Truth: click the empty cell background in Truths mode, or choose Cell in the batch menu.
  • Precise batch input: select candidates with Ctrl/Command or touch long-press, then choose Row, Column, Cell, or Box.
  • Add only proven structural Truths. Extra Truths change Rank and the projection; more is not automatically safer.

13.6 Link Input and Use

A Link is covered at most once and also supports external-candidate elimination tests.

  • Recommended default: leave User Links empty and let the engine derive them.
  • Explicit Links: use for reproducing a specified TLG, constraining the structure, or manual Rank cleanup. House Links normally use same-digit candidates; a Cell Link uses candidates in one cell.
  • Endpoint input: switch to Links, select Link Type, and click two candidates. Auto prioritizes a Cell Link for one-cell endpoints and otherwise interprets shared geometry.
  • Batch input is safer: explicitly choose Row/Column/Cell/Box when geometry could be ambiguous.
  • One User Link is enough to disable automatic Link mixing for that Find. Delete all User Links to restore automatic mode.

13.7 Virtual Set

A Virtual Set expresses an exact cardinality that cannot conveniently be represented by one ordinary R/C/B/N Truth: exactly k selected candidates are true. TLG now supports two independent groups, Virtual Set 1 and Virtual Set 2, each with its own members and cardinality.

  1. Select Virtual Set mode, then choose group 1 or 2 from Virtual Set Group.
  2. Toggle member candidates for that group, or batch-toggle them through the right-click/long-press menu.
  3. Set Truths to Apply to that group's exact cardinality k. Each group independently accepts 1–4.
  4. Verify that every member is active and that external logic proves the exact cardinality of each active group, then run Find.

Relationship between groups: the two groups may be disjoint or may overlap. A selected candidate shared by both groups contributes to both cardinality equations.

Diagram: both groups use black set networks; small 1/2 tabs on candidate badges identify membership. A shared candidate displays both tabs.

Use it when: another argument proves exact 1–4 truths in one or two candidate clouds that are not ordinary house/cell sets.

Do not use it for: “at least one,” “at most two,” or speculative groups. Each group is a strict equality premise.

13.8 Fixed AUR

A fixed AUR supplies a proven swappable uniqueness structure. A standard four-cell AUR is compiled as maxBodyFootprint ≤ 3.

Standard Four-Cell AUR

  1. Select AUR mode and AUR 1 or AUR 2. The two groups represent two independent structures.
  2. For each group, mark exactly two diagonal candidate points with different digits, different rows, and different columns. They define the two rows, two columns, and body pair.
  3. For example, 2r1c1 plus 7r4c5 defines rows r1/r4, columns c1/c5, and digits {2,7}.
  4. Strict mode requires both alternating completions in the initial grid and at least one still live in the current grid.
Do not select all eight body candidates for an ordinary rectangle. The backend pairs marked points; excessive points can produce duplicate or unintended AUR records. The predictable standard input is exactly two diagonal, different-digit points per group.

Mark body-defining candidates, not guardians, target eliminations, or outside candidates.

Advanced generalized AUR: a group of 10–64 points enters generalized/rotating candidate-cloud validation. Use it only when the complete body cloud is known; ordinary UR/AUR work does not need it.

13.9 DAUR

DAUR is a dynamic AUR/DUR pool. The user supplies a small body-candidate pool; the engine expands every valid standard four-cell AUR and six-cell 2×3 / 3×2 DUR found inside it.

  1. Select DAUR mode.
  2. Mark active candidates that may belong to the intended AUR/DUR bodies. Exclude guardians, target eliminations, and unrelated candidates.
  3. Start with the smallest clear pool. The result reports the number of expanded AUR/DUR constraints.
  4. If no valid form expands, check missing body candidates, current live completions, and the initial swap premise under strict mode.

Use it when: several overlapping AUR/DUR forms may exist and manually specifying each one is inconvenient.

Every valid form found in the pool is added simultaneously. DAUR does not choose one “best-looking” pattern. A broad pool can be slower and can introduce structures you did not intend.

13.10 GUR: Purpose, Standard Workflow, and Verified Cases

GUR (Generic Uniqueness Region) validates template-free swappable deadly patterns. Within a user-defined local cell set, the engine enumerates legal one-digit-per-cell completions and compares their row-digit, column-digit, and box-digit exact-cover footprints. Two or more completions with the same footprint can be exchanged without changing the external constraints. GUR compiles those deadly completions into exact no-good constraints, then derives eliminations and assignments shared by every remaining full projection.

Typical uses: irregular deadly patterns, Qiu Deadly Patterns (QDP), some Reversed Deadly Patterns, and local uniqueness structures that cannot be represented accurately by fixed AUR or DAUR four/six-cell templates.

Standard Workflow

  1. Start from an accurate candidate grid: use strict initial-swap validation for states derived from a unique puzzle. Use the training-grid gate only for deliberately constructed training candidates.
  2. Define the local cell boundary: include only active cells that participate in the swappable completions. Exclude guardians, expected eliminations, and cells used only for external links.
  3. Add one Cell Truth for every participating cell: a Cell Truth requires one selected candidate in that cell. Merely marking GUR candidates is not sufficient.
  4. Select the complete GUR cloud: in a closed local model, batch-select any candidate in each participating cell and choose Toggle GUR Cells from the right-click/long-press menu to add every current candidate in those cells at once. When guardians or non-body candidates are present, use Toggle GUR Candidate Cloud afterward for candidate-level corrections. Missing candidates create false restrictions; unrelated candidates enlarge the completion space.
  5. Keep User Links at zero for the first run: let the backend generate Links from the Truths, candidate grid, and GUR. Links displayed after the run are read-only Result Links and are not written back as User Links.
  6. Run Find Eliminations: inspect GUR enumeration constraints, uniqueness-gate status, budgets, eliminations, and assignments. Enter explicit User Links only when reproducing or editing a specified structure.

Success Criteria

  • At least one GUR enumeration constraint is reported, with no missing initial equivalent pair, no missing live deadly completion, and no budget overflow.
  • The projection search completes. When a budget is exceeded, “zero eliminations” does not prove that no elimination exists.
  • The intended elimination or assignment appears in the result. A colored GUR corner tab alone is only a membership marker, not a successful proof.
  • A closed local model can produce additional eliminations or assignments beyond a tutorial's highlighted conclusion. This can be valid because TLG evaluates all complete projections, but the cloud boundary should still be audited.
A GUR currently spans at least 4 and at most 16 cells, with at most 64 candidate points. A typical 18-cell RUR/RUL exceeds the current cell limit and is not yet directly supported.

Troubleshooting Order

  1. Confirm that every participating cell has a Cell Truth and that the GUR cell set matches the Truth coverage.
  2. Audit every cell for all allowed candidates, especially the target cell.
  3. Delete all User Links and retry automatic Links, so a stale explicit structure cannot restrict the search incorrectly.
  4. Check that the uniqueness gate matches the candidate-grid source and that the initial candidates were frozen before editing.
  5. If a budget is exceeded, reduce the local region first; do not interpret the overflow as an invalid pattern.

13.11 Desktop Batch Menu

  1. Hold Ctrl (Command on macOS) and click candidates. Click again to deselect.
  2. Right-click an selected candidate.
  3. Choose Row, Column, Cell, or Box under Truth/Link. If all generated descriptors already exist, the action removes them; otherwise it adds missing ones.
  4. Virtual Set, current AUR group, DAUR, and GUR can also be toggled in batch. Toggle GUR Cells adds/removes all current candidates from the selected candidates' cells, while Toggle GUR Candidate Cloud keeps candidate-level precision.
  5. Clear Candidate Selection clears selection only. Clear All Logic clears TLG logic/result but preserves the temporary TLG candidate grid.

13.12 Mobile / Touch TLG

  • Short tap: executes the current mode. Truth/Link selects the first and second endpoints; VSet/AUR/DAUR/GUR toggles membership.
  • Hold about 0.6 seconds: adds the candidate to batch selection and opens the TLG menu. Submenus open by tap rather than desktop hover; Toggle GUR Cells fills the selected cells with all current candidates in one action.
  • Select several: long-press one candidate, tap outside to close, then long-press another. Long-press is additive; repeat and execute the batch action from the menu.
  • Restart selection: choose Clear Candidate Selection. A normal short tap is not a batch-selection continuation; it runs the current mode and clears the previous batch.
  • Cell Truth: in Truths mode tap empty cell background or an inactive candidate slot rather than an active candidate glyph.
  • Accidental empty-slot input: except for that plain Cell Truth tap, right-click, long-press, Ctrl/Command-click, and clicks in other TLG modes are ignored and cannot alter the underlying Sudoku board.
  • Manual-mark candidate holds are suspended while TLG is active, avoiding touch-handler conflicts.

13.13 Find, Convert, and Remove

  • Find Eliminations: observational. It computes Result Links and conclusions without mutating User Links.
  • Convert Redundant Truths: moves eligible Truths to Links on a valid result structure. Success updates Truths and User Links.
  • Remove Unused Links: removes Links not needed by the proof. Success commits the simplified structure as User Links.
  • Follow-up buttons require a valid elimination/assignment. A failed response preserves the previous valid structure.
  • Any input edit invalidates old Result Links and conclusions, preventing stale highlights from explaining a new structure.

13.14 Highlight Legend

  • Object colors: Cell light blue, Row purple, Column green, and Box brown; structure candidates use blue badges and final eliminations use red badges.
  • Truth / Link: a Truth is a filled region and a Link is the hollow outline of the same geometry. Rows and Columns are continuous bands; a Box is a turning, branching orthogonal network.
  • Cell: the region wraps the active candidate badges belonging to that Cell constraint rather than filling or outlining the whole cell.
  • Candidates: a candidate shared by several Truths/Links still has one badge; the geometry underneath carries the constraint identities.
  • Virtual Sets 1/2: black branching networks with small 1/2 membership tabs; AUR / DAUR / GUR: colored corner tabs rather than outer frames. Candidates shared by both Virtual Sets show both group tabs.
  • Result priority: a final red elimination overrides structure blue; constraint regions are underneath and badges plus interaction accents are on top.

13.15 Result Notation and Budgets

Uppercase R/C/B/N denotes Truths; lowercase r/c/b/n denotes Links; N/n is a cell set. Status distinguishes User Links from Result Links and reports the gate, active candidates, AUR/DAUR/GUR validation, eliminations, and assignments.

Solution-budget, search-node, or GUR local-enumeration budget exceeded means the search is incomplete. Zero eliminations is not proof of none. Reduce the cloud/structure or test a higher budget in native.

13.16 Clearing Commands

  • Delete an item in Current TLG State: removes that user input only.
  • Clear All Logic in the context menu: clears all TLG logic and result while preserving the temporary candidate grid.
  • Clear TLG State in the panel: also removes the temporary candidate grid; the main Sudoku puzzle remains.

13.17 TLG Logic Library

The TLG Library turns a candidate grid, Truth/Link structure, and uniqueness premises into a reusable study case. It is independent of the main-session autosave: the browser library is convenient for daily work, while an exported .tlgdb file is the durable backup for another device, reinstall, or long-term archive.

Fixed-Size Binary Records

The library uses a private YZF binary format with exactly 2048 bytes per record. After the file header, a record is located directly at “header + index × 2048,” making reads, in-place replacement, and ordered management straightforward. Every record has its own CRC32 checksum and the file header is checked as well. Damaged input is rejected before it can change the local library.

Each record stores:

  • original givens, current placed digits, the initial candidate grid, and the current active candidate grid;
  • 324-bit Truths, 324-bit User Links, and computed Result Links;
  • two AUR groups, DAUR, GUR, and two Virtual Sets, each candidate cloud stored as a 729-bit bitmap;
  • the independent cardinality of both Virtual Sets, the selected Virtual Set group, uniqueness gate, input mode, and Link type;
  • the latest eliminations and assignments, plus title, tags, source, and study notes.
The library stores structured data rather than language-dependent result prose. After a record is read, status and result text are regenerated in the current UI language.

Read, Insert, Replace, Append, and Delete

  • Read: restores the candidate grid, all TLG inputs, options, and the result snapshot, then enables TLG editing. The library grid is an independent TLG view; disabling TLG reveals the previous main Sudoku session again.
  • Insert: saves the current TLG before the selected record. With no selection, it behaves like Append.
  • Replace: overwrites the selected record while preserving its position and original creation time.
  • Append: saves the current TLG at the end with a new record ID.
  • Delete: removes the selected record after confirmation.

Title, tags, source, and notes come from the editor on the right. Binary schema v2 remains fixed at 2048 bytes; after reserving the second Virtual Set bitmap, UTF-8 limits are 128 bytes for title, 96 for tags, 128 for source, and 507 for notes. Legacy v1 records with 512-byte notes remain importable. Text beyond the current limit is rejected explicitly.

Binary Library Import and Export

  • Export Selected: creates a .tlgdb containing only the selected record.
  • Export Library: exports every record in the current order.
  • Append to End: imports file records as new records at the end.
  • Insert at Current Position: inserts file records before the selected record in file order; without a selection, it appends.
  • Replace Entire Library: clears the local browser library and loads all file records after a second confirmation.

Sharing One TLG Case as Text

The binary library is for durable storage and bulk management. To share one case in a forum, chat, issue, or notebook, use a .tlg.txt text case. Text actions use the current TLG workspace plus the title, tags, source, and notes currently shown in the library editor, so an unsaved case can be shared directly.

  • Copy Case: copies the readable multiline YZF-TLG-CASE:2 format. VIRTUAL1[k] and VIRTUAL2[k] store the two groups. Legacy YZF-TLG-CASE:1 remains importable.
  • Copy One Line: copies compact YZFTLG2, using W1=/W2= for the two groups. Legacy YZFTLG1 remains importable.
  • Paste Case: attempts to read the clipboard and opens the text box. If browser permission blocks clipboard access, paste into the box manually.
  • Import Text: reads a .tlg.txt or ordinary .txt file into the text box.
  • Export Text: saves the current TLG workspace as title.tlg.txt.
  • Load Case: first shows a parsed summary of title, type, Truth/Link counts, active candidates, and conclusions. Only after confirmation does it replace the temporary TLG state. It does not save into the library automatically; use Insert, Replace, or Append afterward for durable storage.

A text case losslessly stores givens, current placed digits, both candidate bitmaps, Truths, Links, AUR 1/2, DAUR, GUR, Virtual Sets 1/2 with their independent cardinalities, Result Links, eliminations, assignments, options, and metadata. The multiline form uses readable candidate notation such as 7r3c4 and descriptor notation such as 1r3. The complete candidate grids use Base64URL bitmaps. Exported text includes CRC32, so truncated or unintentionally modified content is rejected.

.tlg.txt is convenient for sharing one case, but it does not replace a full-library backup. Both the multiline and one-line forms import into the same structured TLG state.
Clearing site data, ending a private-browsing session, reinstalling the system, or moving to another device can remove the IndexedDB library. Export a .tlgdb after preserving important logic, and additionally copy or export .tlg.txt for individual cases you want to discuss publicly.

14. 内置超难题库 / Built-in Superhard Bank

Insane/超难生成可使用压缩内置题库随机抽取题目，解压后导入当前盘面。轻量压缩 bank 比直接保存 81 字符题串明显更小，并适合 WASM/Standalone 打包。

  • 普通题串：约 81 字节/题。
  • Puzzle19 raw：约 19 字节/题。
  • 压缩 bank：实际大小取决于题库分布，通常更小。

Insane/superhard generation can draw randomly from the compressed built-in bank and import the decoded puzzle. The packed bank is much smaller than storing raw 81-character strings and is suitable for WASM/Standalone builds.

  • Raw puzzle string: about 81 bytes per puzzle.
  • Puzzle19 raw: about 19 bytes per puzzle.
  • Compressed bank: actual size depends on the puzzle distribution and is normally smaller.

16. 手机做题、标记与 TLG / Mobile Solving, Marks & TLG

宽度不超过约 900px 或使用粗指针/触屏时，顶部会出现“做题”。进入后，真实盘面和数字盘会移动到固定视口布局，不会复制第二份盘面，因此编辑、撤销、提示和分析界面始终同步。

手机手动做题的推荐顺序

  1. 载入或生成题目，检查提示数。
  2. 选择“出数”或“候选”，再点大数字 1–9。
  3. 轻触目标格写入出数或切换候选。候选小字难点时，不必直接点小字。
  4. 需要人工分析时点“标记”，按“先选格，再点大数字键”的方式圈候选、上色或暂存删数。
  5. 不确定时点“提示一步”只看结论，确认后再“应用提示”。
  6. 误操作立即撤销；完成阶段性分析后导出候选状态或截图。

顶部与底部按钮

  • 返回：优先关闭当前弹窗、更多抽屉或手工标记；没有内层界面时才退出做题模式并回到原滚动位置。标题栏返回图标右上角数字表示仍可关闭的层数。
  • 新题：选择 ER 难度后生成；已有作答或标记时会警告，确认后清除进度和手工标记。
  • 清除：清除当前选中格的大数字；候选模式下可清除当前选中的候选。
  • 撤销/重做：与主界面共用历史。
  • 标记：打开完整手工标记面板。
  • 更多：打开提示、应用、可选步骤、题面输入、候选显示、同数字高亮、屏幕常亮、全屏、分析模式、帮助与现场和语言。

标题栏状态图标

  • 云朵：显示离线资源下载、完整就绪、当前离线、新版本可用或失败。黄色表示缓存不完整，联网点击会自动补齐；出现“新版本已就绪”时点击会切换到新版本。
  • 软盘：绿色表示已保存，橙色表示有未保存修改，蓝色旋转表示正在保存，红色表示保存失败。切到后台、关闭页面或系统回收页面前会立即刷新保存。
  • 任务列表：有进行中任务时显示数量和蓝色工作状态；点击可查看每项任务的进度、耗时、完成或失败原因。
  • 返回箭头：说明安卓返回键下一步会关闭什么；数字角标表示当前 UI 层级深度。

候选与手工标记

  • 普通候选编辑：先选“候选”和数字，再轻触格子。
  • 候选标记：先选格子，再轻触大数字键添加；长按数字键约 0.5–0.6 秒删除标记。
  • 整格上色：轻触添加，长按格子约 0.6 秒删除。
  • “隐藏候选数”只隐藏显示；进入候选类标记模式会自动重新显示。
  • 长按删除标记不会删除真实候选；正式删数仍需“应用全部删数”。

手机上的 TLG

TLG 属于分析功能，通常先从“分析模式”展开 TLG 面板并启用。开启后，候选触摸由 TLG 接管：

  • 短按候选：执行当前 TLG 输入模式。Truth/Link 用两次短按选择端点；VSet/AUR/DAUR/GUR 短按切换成员。
  • 长按候选约 0.6 秒：加入批选并打开 TLG 菜单。子菜单可直接轻触展开。
  • 多选：长按第一个候选后点菜单外关闭，再长按第二个；选择会累加。选完后从菜单批量加入 Truth/Link/VSet/AUR/DAUR/GUR。
  • 清空批选：使用菜单“清除候选选择”。普通短按会执行当前模式，不适合作为继续批选。
  • Cell Truth：Truths 模式轻触空格背景或已删除候选的空位置。
  • 空位置兜底：除 Cell Truth 的普通轻触外，空位置的右键、长按及其他模式点击都被忽略，不会恢复候选或填入数字。
TLG 与普通手工标记不能同时接管候选长按。开启 TLG 时手工标记暂时隐藏且不响应；关闭 TLG 后恢复。

“更多”里的功能

  • 提示一步 / 应用提示：提示只预览，应用才改盘。
  • 可选步骤：退出做题布局后打开“可选步骤”页签。
  • 题面输入：退出做题布局后展开输入面板并聚焦文本框。
  • 隐藏/显示候选数：只改变显示，不删除候选。
  • 关闭/开启同数字高亮：根据当前数字盘数字，高亮相同大数字。
  • 屏幕常亮：默认开启。进入做题模式时申请 Screen Wake Lock，退出做题模式时释放；切到后台后浏览器会自动释放，重新回到前台时程序会再次申请。关闭该开关后按手机系统的屏保时间正常息屏。
  • 全屏：调用浏览器 Fullscreen API。
  • 分析模式：退出专用做题界面，返回完整分析 UI。

横屏时盘面在左、控制区在右；竖屏时纵向排列并按可用高度缩放。普通全屏在小屏/触屏设备上可能自动进入做题模式，OCR 校正全屏除外。

屏幕常亮需要 HTTPS、localhost 或已安装 PWA 等安全上下文。省电模式、低电量、浏览器或 MagicOS 系统策略仍可能拒绝或临时撤销锁；程序会显示失败提示，但不会修改系统屏保设置。

At widths up to about 900px or with a coarse/touch pointer, the top bar shows Solve. It moves the real board and number pad into a fixed viewport rather than cloning them, so edits, Undo, hints, and analysis remain synchronized.

Recommended Mobile Solving Order

  1. Load or generate a puzzle and verify the givens.
  2. Select Value or Candidate, then choose 1–9 on the large pad.
  3. Tap the target cell to enter a value or toggle a candidate. Tiny candidate glyphs do not need to be targeted for ordinary solving.
  4. For human analysis, open Marks and use “select cell, then large digit” for circles, colors, or staged eliminations.
  5. Use Hint for preview and Apply Hint only after confirming the conclusion.
  6. Undo mistakes immediately; export candidate state or capture the diagram at useful milestones.

Top and Bottom Actions

  • Back: first closes the current dialog, More drawer, or Manual Marks layer. It exits Solve Mode only when no inner layer remains. The badge on the title-bar Back icon shows the remaining depth.
  • New Puzzle: chooses an ER band and generates. Existing progress/marks trigger a warning.
  • Clear: clears the selected user value, or the selected candidate in Candidate mode.
  • Undo/Redo: shares history with the main interface.
  • Marks: opens the full Manual Marks panel.
  • More: opens Hint, Apply, Available Steps, Puzzle Input, candidate visibility, same-digit highlighting, Screen Wake Lock, Fullscreen, Analysis Mode, Help & Workspaces, and language.

Title-Bar Status Icons

  • Cloud: shows offline-resource download, full readiness, current offline state, update availability, or failure. Tap for details; when an update is ready, tapping switches to it.
  • Disk: green means saved, amber means unsaved changes, spinning blue means saving, and red means failure. The session is flushed when the page goes to the background, closes, or is reclaimed by the OS.
  • Task list: shows a count and active state while work is running; open it for per-task progress, elapsed time, completion, or failure details.
  • Back arrow: explains what Android Back will close next. Its badge shows the current UI-layer depth.
  • Temporary feedback: sharing, copying, session restore, and update completion appear briefly, then collapse after about 2–3 seconds.
These icons use fixed title-bar space and do not add a vertical status bar. Tap an icon to read the full English description.

Candidates and Manual Marks

  • Ordinary candidate editing: choose Candidate and a digit, then tap a cell.
  • Candidate marks: select a cell, tap a large digit to add, or hold it about 0.5–0.6 seconds to erase the mark.
  • Cell coloring: tap to add and hold the cell for about 0.6 seconds to erase.
  • Hide Candidates is display-only; candidate mark modes reveal them automatically.
  • Long-press erase does not delete a live candidate. Formal eliminations still require Apply All Eliminations.

TLG on Mobile

TLG is an analysis feature. Open it from Analysis Mode and enable editing; candidate touch is then owned by TLG:

  • Short tap: runs the current TLG mode. Truth/Link uses two endpoint taps; VSet/AUR/DAUR/GUR toggles membership.
  • Hold about 0.6 seconds: adds the candidate to batch selection and opens the TLG menu. Submenus open by tap.
  • Multi-select: long-press one candidate, tap outside to close, then long-press another. Selection accumulates until the batch action is executed.
  • Clear batch selection: use Clear Candidate Selection. A normal short tap executes the current mode rather than continuing batch selection.
  • Cell Truth: tap the empty cell background in Truths mode.
TLG and Manual Marks cannot own candidate long-press simultaneously. Manual marks are hidden and inactive while TLG is enabled, then return afterward.

More Functions

  • Hint / Apply Hint: Hint previews; Apply commits.
  • Available Steps: leaves Solve layout and opens the Available Steps tab.
  • Puzzle Input: leaves Solve Mode, opens the input panel, and focuses the text area.
  • Hide/Show Candidates: changes display only.
  • Disable/Enable Same-Digit Highlight: highlights large digits matching the current pad digit.
  • Keep Screen Awake: enabled by default. Solve Mode requests a Screen Wake Lock and releases it when Solve Mode closes. Browsers release it in the background; the app requests it again after returning to the foreground. Turn the switch off to use the phone's normal sleep timeout.
  • Fullscreen: calls the browser Fullscreen API.
  • Analysis Mode: exits the dedicated solve interface.

Orientation, Images, and Cache

Landscape places board and controls side by side; portrait stacks and scales them. Normal fullscreen may enter Solve Mode automatically on small/touch devices; OCR correction fullscreen is exempt.

Mobile has no reliable Ctrl+V; use Select Image or Take Photo. Chrome Android has no exact Ctrl+F5. After installing an overlay package, close/reopen the page or clear the site cache if the old UI remains.

Screen Wake Lock requires a secure context such as HTTPS, localhost, or an installed PWA. Battery saver, low battery, browser policy, or MagicOS may still reject or release it. The app reports the failure but never changes the system sleep timeout.

缓存与更新规则

  • Service Worker 只有在全部资源校验成功后才激活新版本，避免新 app.js 与旧 Worker/WASM 混用。升级中断时仍继续使用完整旧版本。

  • 断点续传：大型 .wasm 和 .ort 以 1 MiB 分块暂存。网络中断、页面关闭或安装失败后，已完成文件和分块不会删除；重新联网点击云朵或再次检查更新时，从第一个缺失分块继续。
  • 若托管服务器不支持 HTTP Range，程序会自动回退到整文件下载；未变化文件的缓存复用仍然有效。
  • 分享链接中的 ?p=s1.… 不会为每道题重复缓存页面；离线打开时仍由同一份缓存入口恢复题面。
  • 只有浏览器确认新 Service Worker 已真正进入 waiting 状态后，云朵才会变紫并提示“新版本已准备完成”。点击后页面通过 MessageChannel 向该 waiting worker 建立点对点握手；若浏览器曾回收某个暂存文件，worker 会先补齐缺失资源，再执行激活。页面同时监听激活回复、worker 状态和 controllerchange，任一可靠信号确认新版本已激活后都会自动刷新；手动刷新也会继续未完成的切换。
  • 清除浏览器“缓存文件”会要求重新准备被清除的资源；程序会检测缺失项并把云朵变黄，联网点击即可继续补齐。清除“站点数据”会同时删除升级断点、现场、设置和 IndexedDB 中的 TLG 用户题库。

Cache and Update Rules

  • A new Service Worker activates only after every resource has passed verification, preventing a new app.js from being mixed with old Workers or WASM. If preparation is interrupted, the complete previous release remains active.
  • Incremental updates: files are compared by size and SHA-256. Unchanged files are copied from the previous offline cache without network access, so a small release normally downloads only changed JS, HTML, or Manual files.
  • Resumable downloads: large .wasm and .ort files are checkpointed in 1 MiB chunks. Completed files and chunks survive an interrupted connection, closed page, or failed installation; reconnect and tap the cloud to continue from the first missing chunk.
  • If the host does not support HTTP Range, the app automatically falls back to a whole-file download; unchanged-file reuse still applies.
  • Shared ?p=s1.… URLs reuse the same cached app shell instead of creating one cached page per puzzle, and still restore the puzzle offline.
  • The cloud turns purple only after the browser exposes a real waiting Service Worker. Tapping it opens a point-to-point MessageChannel handshake with that worker. If a staged file was evicted, the worker repairs the missing resource before activation. The page watches the handshake, worker state, and controllerchange, then reloads as soon as any authoritative signal confirms activation.
  • Clearing browser cache requires preparing whichever resources were removed. The app detects missing files, turns the cloud yellow, and continues when tapped online. Clearing site data also removes update checkpoints, the saved session, settings, and the IndexedDB TLG user library.

18. Standalone 版本 / Standalone Version

Standalone 版用于离线运行，不需要本地服务器。构建脚本需要把应用 JS、WASM、OCR JS、ONNX Runtime Web、runtime WASM 和两个模型文件内联或打包进单文件 HTML。

  • 普通 Web 版可使用 Solver/Training/Batch Worker；Standalone 会在 Worker 不可用时回退主线程。
  • 浏览器仍可能限制剪贴板、相机、系统分享和文件选择，这与是否离线无关。
  • 单文件体积较大，首次打开和 OCR 首次初始化可能更慢。

若普通版 OCR 正常而 Standalone 失败，检查 ort.min.js、runtime WASM、puzzle_localizer.ort、puzzle_classifier.ort 是否完整内联，并确认 OCR 模块没有残留动态 import() 或本地 fetch()。

The Standalone build runs offline without a local server. Its build script must embed or package the app JS, WASM, OCR JS, ONNX Runtime Web, runtime WASM, and both model files into one HTML file.

  • The regular Web build can use Solver/Training/Batch Workers; Standalone falls back to the main thread when workers are unavailable.
  • The browser may still restrict clipboard, camera, system share, and file pickers independently of offline operation.
  • The single file is large, so first open and first OCR initialization may be slower.

If OCR works in the regular build but fails in Standalone, verify that ort.min.js, runtime WASM, puzzle_localizer.ort, and puzzle_classifier.ort are fully embedded, and that the OCR module has no remaining dynamic import() or local fetch().

标准 AUR 报重复或形成意外结构把四格中很多本体候选都标进同一 AUR 组，后端会两两配对。每个标准 AUR 组只选两个对角、异数字、异行异列候选点。
AUR 提示初始盘没有可交换完成严格门控下，初始候选盘不同时包含两种交替完成，或 OCR/候选导入不完整。核对初始候选和提示数。只有明确的训练盘才改用训练门控。
DAUR 没有展开任何 AUR/DUR候选池缺少本体候选、当前 deadly completion 已消失，或初始交换前提不成立。缩小并核对池，确保只含完整本体候选；查看结果中的验证错误。
DAUR 展开数量很多、运行很慢候选池太宽，程序把其中全部有效 AUR/DUR 同时加入证明。按目标局部结构缩小候选池，移除 guardian、删数目标和无关候选。
GUR 报没有合法完成或没有等价完成对候选云漏候选、混入区域外候选，或该局部结构本身不是可证明 deadly 等价类。重新定义精确格集合和每格允许候选；严格模式还要核对初始候选前提。
GUR 超过预算格数、候选字母表或局部完成数过大。缩小到目标局部区域；上限为 16 格、64 候选点，实际可用规模通常应更小。
Virtual Set 结果不合理把“至少/至多”条件误填成精确基数、当前选择了错误分组，或某个共享候选是否应同时属于两组没有确认。分别检查 Virtual Set 1/2 的成员和基数；每组必须是恰好 k 个真值，k 支持 1–4。共享候选若为真会同时计入两组。
“清空全部逻辑”后候选盘还在右键/长按菜单命令设计为保留临时 TLG 候选盘。要连候选盘一起清除，使用面板“清空 TLG 状态”。
