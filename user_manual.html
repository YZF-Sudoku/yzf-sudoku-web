1. 项目简介 / Overview

YZF Sudoku 是一个面向高级数独技巧分析的 Web/WASM 工具。它支持题串导入、Coach 格式导入、图片本地识别、自动解题、所有步骤搜索、候选数编辑、技巧路径展示和高亮。

项目重点不是只给出答案，而是展示每一步逻辑推理过程，尤其适合研究 AIC、ALS、UR、Oddagon、Force Chain 等高级技巧。

YZF Sudoku is a Web/WASM Sudoku tool focused on advanced solving logic. It supports puzzle-string import, Sudoku Coach formats, local image OCR, auto solving, all-step search, candidate editing, explanation paths, and highlighting.

The goal is not only to produce the final answer, but to show the logical path behind each step, especially for advanced techniques such as AIC, ALS, UR, Oddagon, and Force Chain.

2. 启动方式 / How to Start

普通 Web 版

普通版通常通过本地或在线 HTTP 服务打开，例如开发时可以使用：

cd web-app
python -m http.server 8000

然后访问 http://127.0.0.1:8000/index.html。

Standalone 版

Standalone 版设计目标是双击 HTML 文件即可使用，不需要本地服务器。图片识别所需模型和运行时应已被内联进单文件 HTML。

Regular Web Build

The regular build is usually opened through a local or hosted HTTP server. For development:

cd web-app
python -m http.server 8000

Then open http://127.0.0.1:8000/index.html.

Standalone Build

The standalone build is intended to work by double-clicking the HTML file without starting a server. OCR models and runtime files should be bundled into the single HTML file.

Standalone 版不应依赖 localhost。如果图片识别提示缺少 .ort、.wasm 或 ort.min.js，说明打包流程没有正确内联 OCR 资源。

3. 界面区域 / Interface Layout

  • 盘面区：显示 9×9 棋盘、已知数、出数和候选数。
  • 输入面板：用于输入题串、导入 Coach/Library 格式、图片识别。
  • 技巧面板：选择技巧、搜索下一步、搜索所有步骤。
  • 结果面板：显示删数、路径、解释、评分和状态信息。
  • 导出区域：导出当前盘面、候选数和可分享题串。
  • Board: shows the 9×9 grid, givens, solved digits, and candidates.
  • Input panel: accepts puzzle strings, Coach/Library formats, and image OCR.
  • Technique panel: selects techniques, finds the next step, or searches all steps.
  • Result panel: displays eliminations, paths, explanations, ratings, and status messages.
  • Export area: exports the current board, candidates, and shareable strings.

4. 题面输入 / Puzzle Input

项目支持多种导入格式：

  • 81 字符题串：使用数字 1-9 表示提示数，0 或 . 表示空格。
  • Library 冒号格式：例如 :0000:x:<board>:<eliminations>::，可保存候选删除信息。
  • Sudoku Coach JSON：包含 givenDigits、userDigits、userCellCandidates 等字段。
  • SCv7_32 Coach 压缩串：前端会先解压成 Coach JSON，再导入。

普通导入会进行合法性和唯一解校验；图片识别导入则允许先作为草稿落盘，方便手动校正。

The project supports several import formats:

  • 81-character string: digits 1-9 are givens, while 0 or . means empty.
  • Library colon format: for example :0000:x:<board>:<eliminations>::, preserving candidate eliminations.
  • Sudoku Coach JSON: includes fields such as givenDigits, userDigits, and userCellCandidates.
  • SCv7_32 Coach compressed string: decompressed by the frontend into Coach JSON before import.

Regular imports are checked for validity and uniqueness. OCR imports are allowed to land as editable drafts so the user can correct recognition mistakes.

Coach 候选数 mask / Coach Candidate Masks

userCellCandidates 是 81 个 mask，用 - 分隔。数字 d 对应 1 << d。例如候选 2,3,6 的 mask 是 4 + 8 + 64 = 76。

userCellCandidates contains 81 masks separated by -. Digit d corresponds to 1 << d. For candidates 2,3,6, the mask is 4 + 8 + 64 = 76.

5. 图片识别 / Image Recognition

图片识别在浏览器本地运行，不上传图片，不使用在线 fallback。识别完成后会直接导入为可编辑草稿盘面。

入口一般位于“题面输入 / 导出评分”面板：

  • 选择图片识别：从本地文件或相册选择图片。
  • 拍照识别：手机端调用相机拍摄图片。
  • 从剪贴板识别：桌面端读取剪贴板截图。
  • Ctrl+V：桌面端也可以直接粘贴截图。

Image recognition runs locally in the browser. Images are not uploaded and no online fallback is used. The recognized result is imported directly as an editable draft board.

The buttons are normally placed in the “Puzzle Input / Export & Rating” panel:

  • Select Image: choose an image from files or photo library.
  • Take Photo: open the camera on mobile devices.
  • Read Clipboard: read a screenshot from the desktop clipboard.
  • Ctrl+V: desktop users can paste screenshots directly.

识别结果如何解释 / How OCR Results Are Interpreted

  • 黑色大数字：导入为提示数 givenDigits。
  • 蓝色或其它颜色大数字：导入为出数 userDigits。
  • 小候选数：导入为 userCellCandidates。
  • 非唯一解：不会拒绝导入，而是作为草稿显示，方便校正。

OCR 导入后会用黑色提示数组成的题串做唯一解校验。如果校验失败，仍然允许用户在盘面上继续修正。

  • Black large digits: imported as givens, givenDigits.
  • Blue or other colored large digits: imported as solved/user digits, userDigits.
  • Pencil marks: imported as userCellCandidates.
  • Non-unique result: not rejected; it is shown as a draft so the user can correct it.

After OCR import, the black givens are checked for uniqueness. If the check fails, the draft still remains editable on the board.

图片识别模型使用 Alex Kubiesa / Sudoku OCR 训练的本地模型。项目不使用 sudoku-ocr.com 的在线 fallback。
The OCR feature uses a local model trained by Alex Kubiesa / Sudoku OCR. This project does not use the sudoku-ocr.com online fallback.

6. 盘面编辑 / Board Editing

点击格子后，可以输入数字或候选数。OCR 草稿状态下，修改会直接作用在前端草稿盘面，不会因为当前题面尚未唯一解而被 engine 拒绝。

  • 输入大数字：设置该格出数。
  • 切换候选：在空格中添加或移除候选数。
  • 撤销/重做：回退或恢复最近的盘面操作。
  • 校正完成后，可重新导入或开始搜索技巧。

After selecting a cell, you can enter a digit or toggle candidates. In OCR draft mode, edits are applied directly to the frontend draft board, so the engine will not reject the board simply because the givens are not yet unique.

  • Enter a large digit: set the solved/user digit for the cell.
  • Toggle candidates: add or remove pencil marks in an empty cell.
  • Undo/Redo: revert or restore recent board operations.
  • After correction, you may re-import or start technique search.

7. 自动解题 / Auto Solve

自动解题会从当前盘面开始，按启用技巧和优先级逐步搜索可用步骤，直到解完或找不到下一步。

  • 自动解题：连续应用找到的逻辑步骤。
  • 后台解题：耗时较长的搜索可能显示后台状态提示。
  • 状态信息：会显示 solved、NoResult、Invalid 等结果。

如果自动解题找不到某个高级技巧，请确认该技巧在技巧面板中已启用，并且当前 wasm/standalone 是重新编译或重新生成后的版本。

Auto Solve starts from the current board and searches for logical steps according to the enabled techniques and priority order, until the puzzle is solved or no next step is found.

  • Auto Solve: repeatedly applies available logical steps.
  • Background solving: long searches may display background status messages.
  • Status messages: show results such as solved, NoResult, or Invalid.

If an advanced technique is not found, make sure it is enabled in the technique panel and that the current wasm/standalone file has been rebuilt or regenerated.

8. 所有步骤 / All Steps

“所有步骤”会在当前盘面上收集多个可用步骤，便于比较不同技巧、不同删数和不同路径。

  • 可按技巧类型过滤。
  • 可查看删数、路径、解释和高亮。
  • 对复杂链和 Force Chain，搜索时间可能明显增加。

“All Steps” collects multiple available steps from the current board, making it easier to compare different techniques, eliminations, and paths.

  • Filter by technique type.
  • Inspect eliminations, paths, explanations, and highlights.
  • Complex chains and Force Chains may require noticeably more time.

9. 技巧与高亮 / Techniques and Highlights

项目支持从基础到高级的一系列技巧。高级链类技巧会显示路径、强弱关系、共同删数和特殊构型。

近期重点支持的高级内容包括：

  • AIC / X-Chain / XY-Chain
  • ALS / AHS / XZ 类技巧
  • UR Guardian Force Chain
  • Triplet Oddagon / Tridagon Guardian Force Chain
  • MSLS、JE、Dynamic Chain 等高级迁移技巧

高亮通常包含：链路径、起点、终点、删数、结构格、guardian 候选等。

完整技巧说明：请打开 techniques.html。该页面按玩家阅读方式整理当前已实现技巧的逻辑含义、成立理由和高亮阅读方式。

The project supports a wide range of techniques from basic to advanced. Advanced chain techniques display paths, strong/weak links, common eliminations, and special patterns.

Full technique guide: open techniques.html for player-facing explanations of implemented techniques, conclusions, and highlight reading tips.

Recently supported advanced areas include:

  • AIC / X-Chain / XY-Chain
  • ALS / AHS / XZ-style techniques
  • UR Guardian Force Chain
  • Triplet Oddagon / Tridagon Guardian Force Chain
  • MSLS, JE, Dynamic Chain, and other migrated advanced techniques

Highlights usually include chain paths, starts, ends, eliminations, structure cells, and guardian candidates.

Guardian Force Chain 说明 / Guardian Force Chain

Guardian Force Chain 的通用逻辑是：某个 dead pattern 的所有 guardian 不可能同时为假，因此至少一个 guardian 为真。如果每个 guardian 为真都推出同一个删数，则该删数成立。

UR Guardian FC 和 Triplet Oddagon Guardian FC 的搜索逻辑相同，区别只在 dead pattern 构型不同。

The general logic of Guardian Force Chain is: not all guardians of a dead pattern can be false, so at least one guardian must be true. If every true guardian leads to the same elimination, that elimination is valid.

UR Guardian FC and Triplet Oddagon Guardian FC share the same search logic; only the dead-pattern structure differs.

10. TLG Solver / Truth-Link Logic

TLG Solver 用 Truths、Links、Virtual Set、定式 AUR 和 DAUR/DUR 描述集合逻辑，并搜索这些约束共同推出的删数或出数。只有勾选启用 TLG 编辑后，TLG 才会接管盘面点击和专属高亮。

TLG 编辑期间，普通技巧高亮、链路和手工标记只会暂时隐藏；关闭 TLG 编辑后会恢复，原数据不会被删除。

TLG Solver describes a set-logic proof with Truths, Links, a Virtual Set, fixed AURs, and DAUR/DUR constraints, then searches for eliminations or assignments implied by the combined structure. It takes over board input only while Enable TLG editing is checked.

Ordinary technique highlights, chain overlays, and manual marks are only hidden while TLG editing is active. They return when TLG editing is disabled; their data is not deleted.

核心对象 / Core Objects

  • Truth：投影中必须恰好覆盖一次的集合，可使用行、列、宫或单元格描述符。
  • Link：投影中最多覆盖一次的集合，也用于判断集合外候选是否可删。
  • Virtual Set：由用户直接给出的虚拟约束集合。
  • 定式 AUR：明确指定的四格位置与本体数对 {a,b}。它禁止四格全部由本体数占据，即 maxBodyFootprint ≤ 3。
  • DAUR：用户只标记潜在本体候选池；程序从中动态发现四格 AUR，以及六格 2×3 / 3×2 DUR。所有展开出的约束地位相同，最终必须全部满足。
  • 六格 DUR：六格位置与一个三数组的可交换完成对。它禁止六格全部落入该 deadly completion，即 maxBodyFootprint ≤ 5。
直接使用 maxBodyFootprint 与构造一个“至少一个 guardian 为真”的 1-Truth guardian 集合等价，但不需要先识别 inside/outside guardians。
  • Truth: a set that must be covered exactly once by a projection. Row, column, box, and cell descriptors are supported.
  • Link: a set covered at most once by a projection; it also participates in external-candidate elimination tests.
  • Virtual Set: a user-supplied virtual constraint set.
  • Fixed AUR: an explicit four-cell position plus a body pair {a,b}. It forbids all four cells from being occupied by body digits, represented as maxBodyFootprint ≤ 3.
  • DAUR: the user marks only a pool of potential body candidates. The program dynamically discovers fixed four-cell AURs and six-cell 2×3 / 3×2 DURs. Every expanded constraint has equal status and all of them must be satisfied.
  • Six-cell DUR: a six-cell position and a swappable completion pair for a three-digit set. It forbids all six cells from occupying that deadly completion, represented as maxBodyFootprint ≤ 5.
A direct maxBodyFootprint constraint is equivalent to a one-Truth guardian set saying that at least one guardian must be true, without first classifying inside and outside guardians.

初始候选与唯一性门控 / Initial Candidates and the Uniqueness Gate

TLG 会分开保存初始候选盘与当前候选盘。Sukaku 只是输入格式，并不自动等同于多解训练盘。

  • 唯一解：核验初始可交换局面（默认）
    定式四格 AUR 的初始候选必须同时支持 abba 与 baab 两个可交换完成；当前候选至少保留其中一个。六格 DUR 的初始候选必须支持一对可交换 Latin completion，当前候选至少保留这对中的一个。
  • 训练盘：允许初始缺数
    仅用于人为构造的多解/Rank 训练候选盘。此模式不核验原始唯一性前提，只要求当前候选仍存在至少一个 deadly completion。
普通数独和唯一解 Sukaku 应保持默认严格模式。只有明确用于训练的多解候选盘才应选择“训练盘”。错误放宽可能把不具备交换前提的结构当成 AUR/DUR，产生伪删数。

TLG stores the initial candidate grid separately from the current candidate grid. Sukaku is only an input format and is not automatically treated as a multi-solution training grid.

  • Unique puzzle: verify initial swap pair (default)
    For a fixed four-cell AUR, the initial grid must support both swappable abba and baab completions; the current grid must retain at least one. For a six-cell DUR, the initial grid must support a pair of swappable Latin completions, and the current grid must retain at least one member of that pair.
  • Training grid: allow missing initial candidates
    This mode is only for deliberately constructed multi-solution or Rank-training candidate grids. It skips the original uniqueness premise and requires only a current deadly completion.
Keep the default strict mode for ordinary puzzles and unique-solution Sukaku. Select Training mode only for an explicitly constructed training grid. An inappropriate relaxation can accept an AUR/DUR without a valid swap premise and produce false eliminations.

输入流程 / Input Workflow

  1. 在“操作”页签底部展开 TLG Solver，勾选“启用 TLG 编辑”。
  2. 需要使用候选盘时，把 729 字符 Sukaku 或 81 个候选单元格粘贴到题面输入框，选择正确的“唯一性门控”，再点击“导入 TLG 候选盘面”。导入时的候选会固定保存为初始候选，之后的编辑只改变当前候选。
  3. Truths：点击两个共享同一行、列或宫且数字相同的候选，加入对应 House Truth；点击空单元格背景可切换 Cell Truth。
  4. Links：选择自动、行/列、宫或单元格类型，再依次点击两个候选。自动模式下，同一单元格内的两个候选优先解释为 Cell Link。
  5. 批量选择：按住 Ctrl（macOS 使用 Command）点击候选，再右键打开菜单。可批量添加/移除 Truth 或 Link 的行、列、单元格、宫描述符，也可切换 Virtual Set、AUR 角候选和 DAUR 候选池。
  6. 定式 AUR：选择 AUR 1 或 AUR 2，标记该组四角的实际本体候选。严格模式下，门控会回看初始候选盘验证交换前提。
  7. DAUR：标记潜在本体候选池。程序会动态枚举“4 格位置 + 数对”的定式 AUR，以及“6 格位置 + 三数组交换对”的六格 DUR。
  8. 点击“查找删数”。结果区列出 Truths/Links、定式 AUR、DAUR 展开数量、删数和出数；盘面以红叉显示删数。
  9. 得到有效结果后，可使用“转换冗余 Truths”和“移除未使用 Links”整理结构。转换失败时会保留上一轮有效删数和结果。
“查找删数”“转换冗余 Truths”和“移除未使用 Links”会在后台 Worker 中运行。右键菜单“清空全部逻辑”保留临时候选盘；面板按钮“清空 TLG 状态”会同时清除临时候选盘。
  1. Open TLG Solver at the bottom of the Controls tab and check “Enable TLG editing”.
  2. To use a candidate grid, paste a 729-character Sukaku or 81 candidate-cell tokens into the puzzle input, select the correct Uniqueness Gate, and press “Import TLG Candidate Grid”. The imported candidates are preserved as the initial grid; later edits change only the current grid.
  3. Truths: click two same-digit candidates sharing a row, column, or box to add the corresponding House Truth. Click an empty cell background to toggle a Cell Truth.
  4. Links: choose Auto, Row/Column, Box, or Cell, then click two candidates. In Auto mode, two candidates in the same cell are interpreted as a Cell Link first.
  5. Batch selection: hold Ctrl (Command on macOS), select candidates, then right-click. The menu can batch add/remove Row, Column, Cell, or Box Truth/Link descriptors and toggle the Virtual Set, AUR corners, or the DAUR candidate pool.
  6. Fixed AUR: select AUR 1 or AUR 2 and mark the actual body candidates at its four corners. In strict mode, the gate checks the initial candidate grid for the swap premise.
  7. DAUR: mark a pool of potential body candidates. The program dynamically enumerates fixed AURs as “four-cell position + digit pair” and six-cell DURs as “six-cell position + swappable three-digit completion pair”.
  8. Press “Find Eliminations”. The result lists Truths/Links, fixed AURs, the number of DAUR-expanded constraints, eliminations, and assignments. Eliminations receive a red cross on the board.
  9. After a valid result, use “Convert Redundant Truths” and “Remove Unused Links” to simplify the structure. A failed conversion preserves the previous valid eliminations and result.
Find Eliminations, Convert Redundant Truths, and Remove Unused Links run in a background Worker. “Clear All Logic” in the context menu preserves the temporary candidate grid; “Clear TLG State” also removes that grid.

启用 TLG 编辑后，候选右键菜单只保留以下逻辑操作：

  • 添加/移除 Truth → 行、列、单元格、宫
  • 添加/移除 Link → 行、列、单元格、宫
  • 切换到 Virtual Set
  • 切换 AUR 角候选
  • 切换 DAUR 候选池
  • 清空全部逻辑

执行上述批量动作后，候选选择标记会自动清除。

While TLG editing is enabled, the candidate context menu contains only these proof operations:

  • Add/Remove Truth → Row, Column, Cell, Box
  • Add/Remove Link → Row, Column, Cell, Box
  • Toggle in Virtual Set
  • Toggle AUR Corner
  • Toggle DAUR Candidate Pool
  • Clear All Logic

The multi-candidate selection mark is cleared automatically after any of these batch actions.

结果阅读与预算状态 / Reading Results and Budget Status

结果区采用紧凑集合表示法，例如：

28 Truths = {...}
50 Links = {...}
1 个定式 AUR = ...
DAUR 候选池 = {...}
DAUR 展开 AUR/DUR 约束 = 14
57 个删数 --> r1c1<>1, ...

大写 R/C/B/N 表示 Truth，小写 r/c/b/n 表示 Link；N/n 表示单元格集合。状态栏还会显示当前唯一性门控、候选盘规模和 DAUR 展开数量。

出现“投影解数量超过预算”或“搜索节点超过预算”时，搜索没有完成；此时显示的“0 个删数”不能解释为已证明无删数。应减少结构规模、整理 Truth/Link，或在 native 环境中提高预算继续测试。

The result panel uses compact set notation, for example:

28 Truths = {...}
50 Links = {...}
1 Fixed AUR = ...
DAUR Pool = {...}
DAUR Expanded AUR/DUR Constraints = 14
57 Eliminations --> r1c1<>1, ...

Uppercase R/C/B/N denotes a Truth; lowercase r/c/b/n denotes a Link. N/n is a cell set. The status line also shows the active uniqueness gate, candidate-grid size, and DAUR expansion count.

“Solution budget exceeded” or “search-node budget exceeded” means the search was incomplete. A displayed count of zero eliminations is not proof that no elimination exists. Reduce the structure, simplify Truths/Links, or continue with a larger budget in a native build.

11. 内置超难题库 / Built-in Superhard Bank

项目支持内置超难题库。点击生成超难题时，会从压缩内置题库随机抽取一题，解压并导入当前盘面。

当前轻量方案使用压缩 bank，题库数据段比直接 81 字符文本更小。题库生成工具可以把题串批量打包为 C++ 数据段。

  • 常规题串：约 81 字节/题。
  • Puzzle19 raw：约 19 字节/题。
  • 压缩 bank：实测约 14.4 字节/题，取决于题库内容。

The project supports a built-in superhard puzzle bank. When generating a superhard puzzle, one entry is randomly selected from the compressed bank, decoded, and imported into the current board.

The lightweight design uses a compressed bank, much smaller than storing raw 81-character strings. The packing tool can convert a list of puzzles into a C++ data segment.

  • Raw puzzle strings: about 81 bytes per puzzle.
  • Puzzle19 raw: about 19 bytes per puzzle.
  • Compressed bank: observed around 14.4 bytes per puzzle, depending on the bank.

12. 导出与分享 / Export and Sharing

你可以导出当前盘面用于分享、复现或调试。常见导出内容包括：

  • 普通 81 字符题串。
  • Library 冒号格式，包含候选删除信息。
  • Coach JSON 或 SCv7_32 压缩串。
  • 当前评分、步骤路径和高亮信息。

OCR 导入后如果需要保存校正后的盘面，建议先在盘面上校正，再使用现有导出功能。

You can export the current board for sharing, reproduction, or debugging. Common export contents include:

  • Plain 81-character puzzle string.
  • Library colon format with candidate eliminations.
  • Coach JSON or SCv7_32 compressed string.
  • Current rating, step paths, and highlight information.

After OCR import, correct the board first, then use the existing export feature to save the corrected position.

13. 手机端使用 / Mobile Use

  • 手机没有 Ctrl + V 快捷键，因此应使用“选择图片识别”或“拍照识别”。
  • 如果 Chrome 无法调用相机，先检查 Chrome 的相机权限是否被禁用。
  • 某些浏览器会把“拍照识别”显示为“拍照/相册”选择，这是浏览器行为，不一定是项目问题。
  • 识别后可直接在盘面上修改大数字和候选数。

Chrome Android 刷新缓存

手机端没有完全等同于电脑 Ctrl + F5 的快捷键。开发测试时建议使用版本号参数，或在 Chrome 设置中清除该站点缓存。

  • Mobile devices do not have a Ctrl + V shortcut, so use “Select Image” or “Take Photo”.
  • If Chrome cannot open the camera, check whether camera permission is disabled in Chrome settings.
  • Some browsers show a “camera/gallery” chooser instead of opening the camera directly. This is browser behavior, not necessarily a project bug.
  • After recognition, edit large digits and candidates directly on the board.

Refreshing Chrome on Android

There is no exact mobile equivalent of desktop Ctrl + F5. During development, use versioned URLs or clear the site cache in Chrome settings.

14. Standalone 版本 / Standalone Version

Standalone 版的目标是离线使用，不需要本地服务器。为了支持图片识别，构建脚本需要把 OCR JS、ORT runtime、WASM 和模型文件内联或打包进单文件 HTML。

如果普通 Web 版能识别但 standalone 失败，优先检查：

  • ort.min.js 是否被正确内联。
  • .wasm runtime 是否可用。
  • puzzle_localizer.ort 与 puzzle_classifier.ort 是否被打包。
  • OCR 模块是否还在使用动态 import() 或 fetch() 本地文件。

The standalone build is meant for offline use without a local server. To support image recognition, the build script must inline or bundle the OCR JS, ORT runtime, WASM, and model files into the single HTML file.

If OCR works in the regular Web build but fails in standalone, check:

  • whether ort.min.js is correctly bundled.
  • whether the .wasm runtime is available.
  • whether puzzle_localizer.ort and puzzle_classifier.ort are bundled.
  • whether the OCR module still uses dynamic import() or fetch() for local files.
